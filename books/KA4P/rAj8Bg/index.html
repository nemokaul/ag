Chapter 7. Transformer Architecture

The transformer architecture was introduced in 2017 in the seminal paper “Attention is All You Need” (Vaswani et al., 2017), and has since revolutionized machine learning. Today, transformers form the backbone of state-of-the-art models.

In this chapter, we will review how the transformer architecture works, from its core building blocks to the design choices used in modern large language models. We begin with the three main transformer variants, and then examine the transformer block itself, including self-attention, masked attention, cross-attention, multi-head attention, feed-forward networks, residual connections, and normalization.

We then look at how transformers represent token order through positional encoding. Finally, we connect these components to modern LLM design choices, such as why decoder-only architectures became dominant, how models such as LLaMA and Mistral modify the original Transformer recipe, and how newer approaches such as state-space and hybrid architectures compare. The interview Q&A section goes deeper into the trade-offs, implementation details, and common architecture questions you are likely to encounter in technical interviews.

Transformer Architecture Types

Transformer models can be encoder-based, decoder-based, or encoder-decoder-based.

Encoder-based models consist of a stack of encoder layers that transform the input sequence into context-aware embeddings. This structure is used in models such as BERT for tasks like classification, sentence similarity, and named entity recognition. Figure 7-1 shows the architecture of an encoder-based model that contains N encoder layers.

Figure 7-1. Encoder-only Transformer architecture with N stacked blocks of self-attention and feed-forward layers for generating embeddings.

Decoder-based models consist of a stack of decoder layers that generate output sequences, using both the internal context of previously generated tokens and an autoregressive mechanism. GPT models are decoder-only architectures that excel at text generation, and code synthesis. Figure 7-2 shows the architecture of an decoder-based model.

Figure 7-2. Decoder-only Transformer architecture with N stacked blocks of masked self-attention and feed-forward layers for autoregressive next-token prediction.

Encoder-decoder models combine both components: the encoder processes the input sequence into embeddings, and the decoder generates the output sequence conditioned on these embeddings. This setup is typically used in sequence-to-sequence tasks such as machine translation. T5 and BART models are encoder-decoder based. Figure 7-3 shows the architecture of an encoder-decoder model.

Figure 7-3. Encoder-decoder Transformer structure. The encoder outputs hidden states, which the decoder cross-attention uses as memory. Queries come from the decoder hidden states, while keys and values are projected from the encoder hidden states inside the cross-attention module.

As shown in all figures above, regardless of the type, transformer models are composed of a stack of layers i.e. either encoder layers, decoder layers, or both. Before input text reaches these layers, it first undergoes two preprocessing steps: tokenization and positional encoding.

Tokenization breaks down the raw input text into smaller units called tokens. Tokens can represent words, subwords, or characters depending on the tokenization strategy. Each token is then assigned a unique numerical ID and an embedding vector. Tokenization methods are discussed in detail in the Chapter 8.

Positional Encoding inject information about the position of each token and enable the transformer models to understand the order of tokens in a sequence.

After tokenization and positional encoding, the sequence goes through the transformer layers (also known as transformer blocks). In these layers, attention mechanisms and feedforward networks refine the tokens representations and capture complex dependencies across the sequence.

Transformer Block

A transformer block is the fundamental building block of the transformer architecture. Although its structure may vary slightly between encoder and decoder configurations, its core function remains the same: processing input representations through a series of subcomponents to model the relationships between elements in a sequence.

In a standard encoder or decoder transformer layer, the core components include:

  1. Multi-Head Attention (MHA): This mechanism enables the model to attend to different parts of the input simultaneously. In encoder layers, it consists of self-attention only. In decoder layers, it consists of masked self-attention layers. In encoder-decoder models, both masked self-attention and cross-attention are employed.
  2. Feedforward Neural Network (FFN): A fully connected two-layer network is applied independently to each token to further transform and refine its representation.
  3. Add & Layer Normalization: After each attention and feedforward block, residual connections add the original input back to the output, followed by layer normalization to stabilize training and improve convergence.

Next, we dive into details of each component.

Attention Mechanism

The attention mechanism is a core operation within transformers that enables the model to compute contextual representations of tokens by dynamically assigning importance weights to different parts of the input sequence. This allows the model to capture global dependencies efficiently, rather than relying solely on the local context.

Self-Attention

The simplest form of attention is self-attention, in which each token attends to all other tokens in the same sequence. Variants such as masked self-attention and cross-attention build upon this foundation, as we will explain shortly.

Here is a step-by-step breakdown of the self-attention process:

Step 1) Computing Query (Q), Key (K), and Value (V) Vectors

Each token in the input sequence is initially represented as an embedding vector. Let 𝐗∈ℝn×dmodel denote the matrix of input embeddings, where n is the number of tokens in the input sequence and dmodel is the embedding dimension.

The token embedding 𝐗 is projected into three separate spaces as following:

𝐐=𝐗𝐖Q,𝐊=𝐗𝐖K,𝐕=𝐗𝐖V

where 𝐖Q∈ℝdmodel×dQ,𝐖K∈ℝdmodel×dK, and 𝐖V∈ℝdmodel×dV are learnable parameters. The outcome of these projections are:

  • Query embedding (𝐐∈ℝn×dQ) — represents the token as a “question” about its relationships to other tokens.
  • Key embedding (𝐊∈ℝn×dK) — represents the token as a “descriptor” of its characteristics.
  • Value embedding (𝐕∈ℝn×dV) — contains the token’s information to be passed to other tokens if needed.

Typically dQ=dK as it helps to facilitate computing attention scores.

Step 2) Calculating Attention Scores

The relevance between two tokens is computed as the dot product between their query and key vectors:

score(𝐐,𝐊)=𝐐𝐊T

This produces an n×n matrix, where each entry represents how much one token should attend to another.

Step 3) Scaling the Scores

To stabilize training and prevent excessively large values, the attention scores are scaled by the square root of the key dimension:

scaled scores=𝐐𝐊TdK

Step 4) Applying the SoftMax Function

The scaled scores are normalized using the SoftMax function, turning them into a probability distribution:

Attention Weights=SoftMax(𝐐𝐊TdK)

Each row in the resulting matrix sums to 1, indicating the attention distribution over all tokens for a given token.

Step 5) Computing the Weighted Representation

The final output of the attention mechanism is obtained by computing a weighted sum of the value vectors. Thus, each token’s representation is updated based on information aggregated from the entire sequence, weighted by relevance.

Attention(𝐐,𝐊,𝐕)=Attention Weights×𝐕(1)=softmax(𝐐𝐊TdK)𝐕(2) $Attention(𝐐,𝐊,𝐕)=Attention Weights×𝐕(1)=softmax(𝐐𝐊TdK)𝐕(2)$

The output is a context-aware representation for each token.Figure 7-4 illustrates the attention weight distribution. As you can see, the token "fox" attends strongly to "brown" and "jumps", and moderately to itself and "dog". This leads to a refined representation of "fox" that incorporates both syntactic and semantic cues from its surrounding context.

Figure 7-4. Visualization of the self-attention weight distribution for the token “fox”.

In an interview, being able to writesoftmax(QKT/dk)Vis only the starting point. Be prepared to explain the role of each operation: QKT measures compatibility between tokens, scaling by dk prevents large dot products from saturating softmax, softmax converts the scores into attention weights, and multiplying by V produces the weighted representation. Interviewers often probe the reasoning behind the formula rather than the formula itself.

Masked Self-Attention

In decoder-based models, masked self-attention is used to prevent a token from attending to future tokens. This ensures that predictions are generated autoregressively, where each token can only depend on previous tokens, not future ones. Masking is implemented by assigning a value of −∞ to the attention scores corresponding to future positions before applying the softmax function. This effectively zeros out their contribution, ensuring that the model only attends to past and current tokens when making predictions.

Cross Attention

In encoder-decoder models, cross-attention sublayers allow the decoder to attend not only to its own previous outputs but also to the encoder’s outputs. Here, the queries come from the decoder hidden states, while the keys and values come from the encoder outputs. This enables the decoder to condition its generation on the encoded input sequence.

When comparing transformer architectures in an interview, start with what each token is allowed to attend to. Encoder-only models use bidirectional self-attention, decoder-only models use causal self-attention, and encoder-decoder models add cross-attention from the decoder to the encoder. From there, connect the attention pattern to the training objective and the kinds of tasks the architecture naturally supports. This is clearer than simply listing models such as BERT, GPT, and T5.

Multi-Head Attention

Multi-head attention extends the attention mechanism by employing multiple attention heads, allowing the model to focus on different aspects of the input. Each head computes attention independently, and their outputs are concatenated and linearly transformed:

MultiHead(𝐐,𝐊,𝐕)=Concat(head1,head2,…,headh)𝐖O

where headi=Att(𝐐𝐖iQ,𝐊𝐖iK,𝐕𝐖iV), and 𝐖O, 𝐖iQ, 𝐖iK, and 𝐖iV are learnable weight matrices.

Each attention head produces an output of dimension dV. Concatenating the outputs of all h heads results in a vector of dimension h·dV. The matrix 𝐖O is a learnable projection that transforms this combined output back to the original model dimension dmodel, ensuring compatibility with subsequent layers in the network.

Example: Multi-Head Attention Example

Suppose we have a sentence:"The cat sat on the mat"

A single attention head might focus on nearby tokens (e.g., "sat" attends to "cat"), capturing local syntax. Another head might focus on repeated words (e.g., both "the"s), while a third head might focus on semantic roles (e.g., subject and object).
Multi-head attention allows the model to learn these patterns in parallel and combine them for a richer representation.

Feed-Forward Network (FFN)

The feed-forward network (FFN) is a position-wise multilayer perceptron applied to each token independently after the attention sublayer. While attention mixes information across tokens, the FFN transforms each token’s representation separately using the same learned weights at every position.

In the original Transformer, the FFN is defined as:

FFN(𝐱)=ReLU(𝐱𝐖1+𝐛1)𝐖2+𝐛2,

where 𝐖1, 𝐖2, 𝐛1, and 𝐛2 are learnable parameters.

Figure 7-5 shows the architecture of an FFN. The first linear layer usually expands the hidden dimension, the activation introduces non-linearity, and the second linear layer projects the representation back to the model dimension.

Figure 7-5. Feed-forward network (FFN) in a Transformer block. The first linear layer expands the representation and applies a nonlinear activation; the second linear layer projects it back to the original dimension.

Modern LLMs replace the ReLU (Rectified Linear Unit) function with smoother or gated activations such as GELU (Gaussian Error Linear Unit), SiLU (Sigmoid-Weighted Linear Unit), or SwiGLU (Swish Gated Linear Unit). SwiGLU has become the de facto default in recent open models (LLaMA, Mistral, Qwen, Gemma); it uses three weight matrices instead of two and a smaller expansion factor (typically 83d rather than 4d) so the total parameter count stays comparable. We return to this in the LLaMA recipe later in the chapter.

Example: Feed-Forward Network Example

Suppose after attention, the embedding for a token is 𝐱=[0.2,0.4,−0.1,0.0].

After passing through the FFN (with learned weights and biases), the vector might become FFN(𝐱)=[0.1,0.9,0.0,−0.2]. This transformation enables the model to re-project contextualized token embeddings into more expressive feature spaces.

Residual Connection and Layer Normalization

To facilitate gradient flow, stabilize training, and improve optimization, the transformer architecture integrates residual connections and layer normalization in its design. These mechanisms are applied around each sublayer, enhancing learning dynamics. Specifically, transformers can utilize pre-layer normalization or post-layer normalization, both depicted in Figure 7-6.

Figure 7-6. Post-LayerNorm and Pre-LayerNorm structures in Transformer models.

In the post-layer norm approach, the input x is first passed through the sublayer function SubLayer(.), and the residual connection is applied before normalizing the result. The output is computed as:

Output=LayerNorm(𝐱+SubLayer(𝐱))

This formulation ensures that residual connections are directly added to the sublayer output before normalization.

In contrast, in the pre-layer norm approach, the input is normalized before passing through the sublayer, improving training stability in deeper models. The computation is given by:

Output=𝐱+SubLayer(LayerNorm(𝐱))

Where the residual connection acts on the sublayer output directly, avoiding reliance on layer normalization for gradient propagation.

In practice, many modern transformer models use pre-layer normalization because it leads to better gradient flow in very deep networks. The residual connection ensures that the original input is preserved and refined, while layer normalization helps control the scale of activations.

Do not describe the 2017 Transformer architecture as if modern LLMs use it unchanged. A useful interview comparison is: the original Transformer used post-LayerNorm, ReLU-based feed-forward networks, sinusoidal positional encoding, and standard multi-head attention. Modern decoder-only LLMs commonly use variants such as pre-normalization, RMSNorm, SwiGLU, RoPE, and grouped-query attention. The transformer block has remained recognizable, but many of its components have evolved.

Positional Encoding

Transformers process all tokens in a sequence in parallel. This is one of the reasons they are efficient, but it also creates an important problem: the self-attention mechanism does not inherently know the order of tokens. Without additional positional information, the transformer would treat a sequence more like an unordered set of tokens than an ordered sentence.

For example, the sentences “the cat chased the dog” and “the dog chased the cat” contain the same words, but their meanings are different because the token order is different. A transformer needs a way to distinguish not only which tokens appear, but also where they appear.

Positional encodings solve this problem by injecting information about token position into the model. In the simplest form, positional encodings are vectors that have the same dimensionality as token embeddings and are added to those embeddings before the input is passed into the transformer layers:

𝐱i′=𝐱i+𝐩i

where 𝐱i is the token embedding at position i, 𝐩i is the positional encoding for position i, and 𝐱i′ is the final input representation.

This means each token representation contains two kinds of information: what the token is and where it appears in the sequence. If the same word appears in two different positions, the token embedding may be the same, but the final input vector will be different because the positional encoding is different.

There are several approaches to positional encoding. Some methods add positional vectors directly to token embeddings, while others inject positional information into the attention mechanism itself.

Absolute Positional Encoding

The original Transformer paper, Attention Is All You Need, used absolute positional encodings. In this approach, each token receives a position representation based on its fixed index in the input sequence: position 0, position 1, position 2, and so on.

Absolute positional encodings are commonly implemented in two ways: sinusoidal positional encodings and learned positional embeddings.

Sinusoidal positional encoding.

Sinusoidal positional encodings are fixed, parameter-free vectors generated using sine and cosine functions of different frequencies. For position p and dimension i, the encoding is defined as:

PE(p,2i)=sin(p100002i/dmodel)

PE(p,2i+1)=cos(p100002i/dmodel)

where p is the token position, i is the dimension index, and dmodel is the hidden size of the model.

The intuition is that each dimension of the positional encoding varies at a different frequency. Some dimensions change quickly across nearby positions, while others change slowly over longer distances. This gives the model a smooth representation of position and allows it to reason about relative distances between tokens.

A key advantage of sinusoidal encodings is that they do not introduce additional learned parameters. They can also be computed for sequence lengths longer than those seen during training, which gives them some ability to extrapolate to longer contexts.

Learned positional embeddings.

Another approach is to learn a separate embedding vector for each position. In this case, the model maintains a positional embedding table, similar to a token embedding table:

𝐩i=PositionEmbedding(i)

These position vectors are randomly initialized and trained along with the rest of the model. Learned positional embeddings can adapt to patterns in the training data and may work well when the model is always used with sequence lengths similar to those seen during training.

The main limitation is that learned absolute positional embeddings do not naturally extrapolate to longer sequences. If the embedding table was trained only up to position 512, the model does not automatically know what embedding to use for position 1024.

Example: Sinusoidal Positional Encoding Example

Let’s consider a short sequence of 4 tokens:
["The", "cat", "sat", "down"]

Assume dmodel=4. Each token is initially mapped to an embedding vector as follows:

TokenEmbedding
The[0.1, 0.2, 0.3, 0.4]
cat[0.2, 0.3, 0.1, 0.0]
sat[0.5, 0.1, 0.2, 0.2]
down[0.0, 0.3, 0.3, 0.1]

Now, let’s compute sinusoidal positional encodings for positions 0 to 3. The resulting vectors might look like:

PositionPE Vector
0[0.0000, 1.0000, 0.0000, 1.0000]
1[0.8415, 0.5403, 0.0100, 0.9999]

The final input to the transformer is the sum of each token’s embedding and its positional encoding:

Input=Embedding+Positional Encoding

This ensures that even if the same word appears more than once, its representation will differ depending on its position in the sequence.

Relative Positional Encoding

Absolute positional encodings tell the model where each token is located relative to the beginning of the sequence. However, for many language tasks, the relative distance between tokens matters more than their absolute position.

Relative positional encoding captures relationships such as “this token is three positions before that token” or “these two tokens are nearby.” Instead of only encoding the absolute position of each token, relative methods inject information about the distance between pairs of tokens.

A common way to do this is to add a relative position bias directly to the attention scores:

Attention(𝐐,𝐊,𝐕)=softmax(𝐐𝐊⊤+𝐁reldk)𝐕

where 𝐁rel is a bias matrix whose values depend on the relative distance between token positions.

Relative positional encodings are especially useful when the model needs to generalize across different sequence lengths or focus on local and long-range relationships. They are more flexible than simple absolute positions, but they are also more complex to implement and less directly interpretable.

Rotary Positional Embeddings (RoPE)

Rotary Positional Embeddings, commonly called RoPE, inject positional information directly into the attention mechanism by rotating the query and key vectors according to their positions.

Instead of adding a positional vector to the token embedding, RoPE applies a position-dependent rotation to the query and key vectors:

𝐪~i=Ri𝐪i,𝐤~j=Rj𝐤j

where Ri and Rj are rotation matrices determined by positions i and j. When the rotated query and key vectors are compared in the attention score, their dot product naturally depends on the relative distance between positions:

𝐪~i⊤𝐤~j≈f(j−i)

This makes RoPE behave like a relative positional encoding while remaining efficient and smooth. RoPE has become popular in modern autoregressive language models, including LLaMA-style architectures, because it works well for long-context modeling and does not require adding separate positional vectors to the input embeddings.

Attention with Linear Biases (ALiBi)

Another related method is Attention with Linear Biases, or ALiBi. Instead of adding positional embeddings to token representations, ALiBi adds a distance-based linear bias directly to the attention scores. Tokens that are farther away receive a larger penalty, encouraging the model to pay more attention to nearby tokens while still allowing long-range attention.

Like relative positional encodings, ALiBi modifies the attention computation rather than the input embeddings. It is simple, parameter-efficient, and useful when extrapolation to longer sequence lengths is important.

Comparing Positional Encoding Methods

Each positional encoding method makes a different trade-off between simplicity, flexibility, extrapolation, and compatibility with the transformer architecture. Table 7-1 summarizes these trade-offs.

Table 7-1. Comparison of positional encoding methods in transformers

MethodNotes
Sinusoidal absolute encoding+ Fixed and parameter-free. + Simple to implement. + Can be computed for longer sequence lengths. - Less flexible than learned embeddings. - May be suboptimal for tasks where learned position patterns matter.
Learned absolute encoding+ Learns task-specific positional patterns. + Often works well for fixed maximum context lengths. - Adds extra parameters. - Does not naturally extrapolate beyond the trained sequence length.
Relative positional encoding+ Models token-to-token distances directly. + Useful when relative order matters more than absolute position. + Can generalize better across sequence lengths. - More complex than absolute encoding. - Requires modifying the attention computation.
RoPE+ Encodes relative position through query-key interactions. + Effective for autoregressive and long-context models. + Does not require adding positional vectors to embeddings. - Requires modifying query and key representations. - Long-context extrapolation may still require careful scaling.
ALiBi+ Simple and parameter-efficient. + Adds position information directly to attention scores. + Useful for extrapolating to longer contexts. - Less expressive than learned or rotary methods. - Encodes distance through a fixed bias pattern.

The right positional encoding method depends on the model architecture and the task.

Sinusoidal encodings are useful when a simple, fixed, parameter-free method is preferred. Learned absolute embeddings are suitable when the maximum sequence length is fixed and the model is expected to operate mostly within the training distribution. Relative positional encodings are useful when relationships between tokens matter more than their absolute positions, such as in translation, question answering, or structured sequence tasks. RoPE is a strong choice for modern autoregressive LLMs that need to handle long contexts efficiently. ALiBi is useful when simple long-context extrapolation is important.

In modern LLMs, positional information is not always added only once at the input layer. In the original transformer architecture, positional encodings are added to the input embeddings, and the position information is carried through the hidden states across layers. In methods such as relative positional encoding, RoPE, and ALiBi, position information is instead injected directly into the attention computation.

When discussing efficiency improvements, be precise about which layer of the system changed. FlashAttention, for example, is not a new attention architecture: it computes the same attention function while changing how the computation is tiled and moved through GPU memory. By contrast, methods such as grouped-query attention or sliding-window attention change the model’s attention structure itself. Making this distinction shows that you can separate model architecture from systems-level optimization.

Summary

The transformer architecture is a highly modular and parallelizable framework that has become the foundation for a wide range of NLP tasks. Its use of attention mechanisms, positional encodings, and feed-forward networks addresses the limitations of previous models and enables state-of-the-art performance on language understanding and generation tasks. In the next section, we will explore specific questions and answers related to transformers, delving deeper into their components and applications.

Interview Questions and Answers

Thread: Why Transformers?

  1. What advantages do transformers have over prior architectures like RNNs and CNNs?
    Several properties separate transformers from recurrent models:
    • Parallel processing: Transformers process all tokens simultaneously through matrix operations. RNNs must process tokens one by one because each hidden state depends on the previous step.
    • Direct long-range access: Self-attention lets any token attend directly to any other token, regardless of distance. In an RNN, information from an early token must survive through every intermediate hidden state to reach a late token. Over long sequences, the hidden state compresses earlier information, and the model effectively “forgets” early tokens.
    • No vanishing gradient bottleneck: RNNs update weights through backpropagation through time (BPTT), which multiplies gradients across every time step. When activation functions like sigmoid or tanh produce derivatives below 1, successive multiplications cause gradients to shrink exponentially, making it nearly impossible to learn from distant tokens. Transformers avoid this entirely: attention provides a direct gradient path between any two positions without a chain of multiplicative steps.
    • Hardware-friendly scaling: The core operations, matrix multiplications and softmax, map naturally onto GPU and TPU architectures, making transformers far easier to scale than sequential models.
      CNNs bring a different limitation. They capture local patterns through fixed-size convolutional filters, so modeling a dependency between two tokens that are far apart requires stacking many layers until the receptive field is large enough to cover both positions. Self-attention connects every token pair directly in a single layer, regardless of distance. CNNs also encode position implicitly through the structure of their layers, which can be imprecise for language, whereas transformers use explicit positional encodings, giving them finer control over how order information enters the computation.
      That said, CNNs remain competitive for short, fixed-length inputs where local patterns dominate, for example character-level classification. For most language tasks, the global context and parallelism of transformers make them the stronger choice.
  2. Self-attention has O(n2) complexity. Why is that acceptable?
    The quadratic factor comes from computing the n×n attention matrix, where every token pair receives a score. The full cost is O(n2d) when you include the embedding dimension d in each dot product, but d is fixed by the architecture, so the sequence length n is what drives the scaling. For moderate sequence lengths, up to a few thousand tokens, the n2 cost is manageable because the matrix operations are highly parallelizable on modern GPUs, and the constant factors are small.
    At very long sequences, 32K, 128K, or more, the quadratic cost does become a bottleneck. The field addresses this through several strategies:
    • FlashAttention: An implementation-level optimization that tiles the attention computation to minimize memory transfers between GPU SRAM and HBM. The math is identical; only the memory access pattern changes.
    • Sliding window attention: Restricts each token to attend only within a fixed-size local window, for example 4,096 tokens, reducing cost to O(n·w) where w is the window size.
    • Sparse and linear attention: Approximate attention mechanisms that reduce the cost below O(n2), though often at some quality cost.
      For long contexts, systems combine implementation optimizations such as FlashAttention with architectural techniques such as GQA and sliding-window attention to reduce compute and memory costs.

Thread: Attention from First Principles

  1. Walk me through the self-attention mechanism step by step.
    Self-attention lets every token gather relevant information from all other tokens in the sequence. Given an input matrix X∈ℝn×d, one row per token, it proceeds in five steps:
    1. Project into Q, K, V: Multiply X by three learned weight matrices:
      Q=XWQ,K=XWK,V=XWV
      Q (query) represents what each token is looking for. K (key) represents what each token offers. V (value) carries the actual information to be retrieved.
    2. Compute raw scores: Take the dot product of queries with all keys:
      Scores=QKT∈ℝn×n
      Entry (i,j) measures how relevant token j is to token i.
    3. Scale: Divide by dk to prevent the scores from growing too large:
      Scaled Scores=QKTdk
    4. Softmax: Normalize each row into a probability distribution:
      Attention Weights=softmax(QKTdk)
    5. Weighted sum of values:
      Output=Attention Weights×V
      Each token’s output is a weighted blend of all value vectors, where the weights reflect relevance.
      The complete formula is:
      Attention(Q,K,V)=softmax(QKTdk)V
      The dot product is not the only way to score compatibility. A historical alternative is additive (Bahdanau) attention, which uses a small neural network instead of a dot product:
      eij=vaTtanh(WQqi+WKkj)
      where va, WQ, and WK are learned parameters. Because it learns a nonlinear scoring function, additive attention is more flexible and does not assume that the raw dot product captures relevance. Scaled dot-product attention is faster because it reduces to a single matrix multiplication, which is why transformers use it. Additive attention (Bahdanau et al., 2015) is primarily of historical interest; it was the standard in early sequence-to-sequence models before the transformer was introduced.
  2. Why do we need three separate projections (Q, K, V) instead of just one?
    Using a single shared projection would force every token to play all three roles with the same representation. Separate projections let the model learn what to ask for (Q), what to advertise (K), and what to send (V) independently.
    Consider translation: when generating the word “bank,” the query might encode “I need a financial term,” the key for “river” would not match strongly, and the key for “account” would. Meanwhile, the value for “account” carries the actual semantic content to incorporate. Collapsing these three functions into one vector would make it much harder for the model to learn such selective retrieval.
  3. Why do we scale by dk?
    Each entry in QKT is a sum of dk terms. When Q and K entries have roughly unit variance, the Central Limit Theorem tells us the sum has variance proportional to dk. As dk grows, some dot products become very large and others very small.
    Softmax amplifies these differences exponentially. A score of 50 versus 5 produces a near-one-hot distribution, meaning the model attends almost entirely to a single token. The gradients for all other positions nearly vanish, which stalls learning.
    Dividing by dk rescales the scores so their variance stays close to 1 regardless of the dimension. Softmax then produces smoother distributions, and gradients flow to all positions.
  4. What is the difference between self-attention, masked self-attention, and cross-attention?
    • Self-attention: Every token attends to every other token in the same sequence, including itself. Used in encoder-only models such as BERT. The attention matrix is dense.
    • Masked (causal) self-attention: Each token can attend only to itself and to tokens that come before it. A mask sets future positions to −∞ before softmax:
      MaskedScoreij={QKTdkif j≤i−∞if j>i
      After softmax, future positions receive zero weight. Used in decoder-only models such as GPT and LLaMA to enforce autoregressive generation: the prediction for position t cannot depend on positions t+1,t+2,….
    • Cross-attention: The queries come from one sequence, typically the decoder, and the keys and values come from a different sequence, typically the encoder output. Used in encoder-decoder models such as T5 and BART so the decoder can condition on the encoded input.
  5. Why use multiple attention heads instead of a single large one?
    A single attention head computes one set of attention weights per token pair. If a word is both syntactically and semantically related to different parts of the sentence, a single head must compress both relationships into one distribution.
    Multi-head attention runs h independent attention computations in parallel, each in a d/h-dimensional subspace:
    MultiHead(Q,K,V)=concat(head1,…,headh)WO
    where headi=Attention(QWiQ,KWiK,VWiV).
    Each head can specialize: one head might capture local syntax, such as subject-verb agreement, another might track coreference, such as which noun a pronoun refers to, and another might attend to positional patterns. The output projection WO recombines these perspectives into a single representation.
    The total parameter count is the same as a single head of the same total dimension, since each head works in a smaller subspace, d/h per head.

Thread: Inside a Transformer Block

  1. What are the core components of a transformer block?
    A single transformer block, sometimes called a transformer layer, contains:
    1. Multi-head attention: Mixes information across tokens by computing attention-weighted combinations of value vectors. In a decoder block, this is masked, or causal, self-attention.
    2. Feed-forward network (FFN): A position-wise MLP applied independently to each token’s representation. It introduces nonlinearity and transforms individual token embeddings.
    3. Residual connections: An additive skip connection around both the attention sublayer and the FFN sublayer, so the input is added back to the output: out=x+f(x).
    4. Normalization: Layer normalization, or RMSNorm in modern models, applied either before each sublayer (pre-norm) or after the residual addition (post-norm).
      A transformer model stacks many of these blocks, for example 32 for LLaMA-7B and 80 for LLaMA-70B. The final block’s output is projected through the language modeling head to produce next-token probabilities.
  2. What role does the FFN play, why does it expand to 4× the model dimension, and what happens if you shrink it?
    The attention output is a weighted sum of value vectors. While softmax introduces a nonlinearity in computing the mixing weights, no learned nonlinear function like ReLU or GELU is applied to the values themselves. The FFN introduces the learned nonlinear transformations that give the model its representational power. In the standard design:
    FFN(x)=ReLU(xW1+b1)W2+b2
    where W1∈ℝd×4d expands the dimension and W2∈ℝ4d×d projects back down.
    The 4× expansion creates a higher-dimensional intermediate space where the model can learn richer feature interactions before compressing back. Studies have shown that FFN layers function as key-value memory stores: the first layer’s rows encode patterns, and the second layer stores the associated information. The 4× multiplier is a convention from the original transformer paper; it is not a theoretically derived optimum, but it has proven to be a robust default.
    Shrinking the FFN has clear consequences. It accounts for roughly two-thirds of each layer’s parameters, since it uses two large weight matrices of size d×4d and 4d×d, compared to four d×d matrices in attention. Reducing the expansion factor from 4d to, say, 2d cuts the FFN parameters in half, which reduces memory and latency, but the smaller intermediate space limits the nonlinear feature interactions the layer can represent, which can degrade quality. Most designers keep the standard ratio and reduce cost elsewhere; MoE is one alternative, using many smaller expert FFNs but activating only k per token.
  3. Why are residual connections essential in transformers?
    Without residual connections, each sublayer must learn the entire transformation from input to output. With a skip connection, out=x+f(x), the sublayer only needs to learn the residual, meaning what to add or change. Learning a small correction is easier than learning the full mapping.
    Residual connections also provide a direct gradient path from the output back to early layers. In a deep model, 32 to 80+ layers, gradients that must pass through every sublayer sequentially tend to shrink, vanishing gradients, or explode. The skip connection creates a shortcut that preserves gradient magnitude.
    Removing residual connections from a transformer typically causes training to diverge or converge to a much worse solution, especially in deeper models.
  4. Pre-norm vs. post-norm: what is the difference?
    Post-norm, the original transformer design, applies normalization after the residual addition:
    out=LayerNorm(x+f(x))
    Pre-norm applies normalization before the sublayer:
    out=x+f(LayerNorm(x))
    Pre-norm places the residual connection on a clean, unnormalized path from input to output. Gradients flow through this path without being rescaled by normalization, which makes training more stable in deep models. Most modern LLMs, including LLaMA, Mistral, and PaLM, use pre-norm (GPT-2 and GPT-3 helped establish it).
    Post-norm can sometimes produce slightly better final performance when training is stable, but it requires more careful learning rate warmup and initialization. For the depths used in current LLMs, 32 to 100+ layers, pre-norm is the safer and dominant choice.
  5. How do RMSNorm, LayerNorm, and BatchNorm compare, and why do transformers avoid BatchNorm?
    Transformers avoid BatchNorm for two main reasons:
    • Variable-length sequences: BatchNorm computes statistics across the batch dimension, which requires all sequences in the batch to contribute to the same mean and variance. When sequences have different lengths, which is common in NLP, the batch statistics become noisy and unreliable. LayerNorm computes statistics across the feature dimension of each individual token, independent of other sequences.
    • Batch size dependency: BatchNorm requires a reasonably large batch to compute stable statistics. During LLM inference, the batch size is often 1, making batch statistics meaningless. LayerNorm computes statistics per token, so it works identically regardless of batch size.
      Standard LayerNorm normalizes activations by subtracting the mean and dividing by the standard deviation, then applies learnable scale γ and shift β parameters:
      LayerNorm(x)=γ·x−μσ2+ϵ+β
      RMSNorm refines this further. It drops the mean-centering step and the shift parameter, normalizing by the root mean square only:
      RMSNorm(x)=γ·x1d∑i=1dxi2+ϵ
      Removing the mean computation and the β parameter makes RMSNorm faster, with reported speedups of 7—​64% depending on implementation, with negligible quality difference in practice. The empirical finding is that the rescaling, dividing by the norm, matters far more than the recentering, subtracting the mean. LLaMA, Gemma, PaLM, and most open-source LLMs from 2023 onward use RMSNorm.
      Without any normalization at all, activations drift to extreme values across layers, gradients become unstable, vanishing or exploding, and training either diverges or requires very careful learning rate and initialization tuning. Normalization is not optional in deep transformers.

Thread: Positional Encoding

  1. Why do transformers need positional encodings?
    Self-attention is permutation-equivariant: if you shuffle the input tokens, the output shuffles in the same way. The mechanism has no built-in notion of which token comes first, second, or last. Without positional information, the sentences “the cat chased the dog” and “the dog chased the cat” would produce identical attention patterns.
    Positional encodings inject order information so the model can distinguish positions. Depending on the method, this information is either added to the input embeddings or incorporated directly into the attention computation.
  2. What are the main types of positional encoding, and where is each applied?
    1. Sinusoidal (fixed absolute): Uses sine and cosine functions of varying frequencies to produce a unique vector for each position:
      PE(p,2i)=sin(p100002i/d),PE(p,2i+1)=cos(p100002i/d)
      It is added to token embeddings once, before the first layer; positional information is then carried implicitly through the hidden states, and can degrade in very deep models. It requires no learned parameters and can generalize to positions not seen during training.
    2. Learned absolute: A lookup table of trainable vectors, one per position. Each position index maps to a learned embedding that is added to the token embedding once, before the first layer, so its positional signal also carries implicitly through the hidden states and can degrade in very deep models. This is more flexible than sinusoidal on in-distribution lengths, but cannot extrapolate to longer sequences because the table has no entry for unseen positions.
    3. Relative positional encoding: Adds a learned bias to the attention scores at each layer based on the distance between tokens rather than their absolute positions. It generalizes better to varying lengths because the model only needs to know how far apart two tokens are.
    4. Rotary Positional Encoding (RoPE): Applies rotation matrices to the query and key vectors at every layer, not just the input, so that the dot product qiTkj naturally encodes the relative distance j−i. Because each layer receives fresh positional signal, RoPE performs well in deep models. Used in LLaMA, Mistral, and most modern open-source LLMs.
    5. ALiBi (Attention with Linear Biases): Subtracts a linear penalty proportional to token distance directly from the attention scores:
      score(i,j)=qiTkj−m·|i−j|
      where m is a head-specific slope. The linear bias is added at every layer. It has no learned parameters and offers good length extrapolation. Used in MPT and BLOOM.
      Positional encodings always match the model’s hidden dimension d in size, or, for methods that modify attention scores rather than embeddings, they match the n×n score matrix. This dimensional matching is what allows the positional signal to be added directly to token embeddings or attention scores without reshaping.
  3. How does RoPE work, and why has it become the dominant choice?
    RoPE encodes position by rotating query and key vectors in 2D subspaces. For a pair of adjacent dimensions (x2k,x2k+1), RoPE applies a rotation by angle p·θk, where p is the token position and θk is a frequency that decreases with dimension index, similar to the sinusoidal scheme.
    The key property is that after applying RoPE to both qi and kj, their dot product depends only on the relative position j−i, not on the absolute positions individually. Each token still gets a unique rotation, so absolute position is encoded, but the attention score reflects relative distance.
    RoPE became dominant for several reasons:
    • It captures relative position without adding extra parameters.
    • It is applied at every layer, not just the input, giving each layer fresh positional signal.
    • It supports context length extension through techniques like position interpolation, NTK-aware scaling, and YaRN, which modify the frequency basis to let models trained at 4K or 8K context reach 128K+.
      Nearly all open-source LLMs since 2023 use RoPE: LLaMA 1/2/3, Mistral, Qwen, DeepSeek, and Gemma.
  4. How do you extend a model’s context length beyond what it was trained on?
    The challenge is that positional encodings, especially learned absolute ones, degrade at positions they never saw during training. RoPE-based models have a more principled path to extension:
    • Position interpolation: Instead of extrapolating to new positions, compress the position indices so they fit within the original range. A model trained at 4K context divides all position indices by 4 to handle 16K context. This usually requires a small amount of continued training to adapt.
    • NTK-aware interpolation: Adjusts the frequency base of RoPE rather than uniformly scaling positions. High-frequency components, which encode fine-grained local position, are left mostly unchanged, while low-frequency components, which encode global position, are stretched. This preserves local attention patterns.
    • YaRN: Combines NTK-aware interpolation with an attention temperature scaling factor. It achieves strong context extension with minimal fine-tuning.
      These techniques have enabled models trained at 8K context to function well at 128K or beyond, for example LLaMA 3.1 supports 128K context. The Long Context Modeling chapter explores these methods in greater detail.

Thread: Architecture Types and Why Decoder-Only Won

  1. Why did decoder-only architectures become the standard for LLMs?
    Several factors converged:
    • Simpler architecture, easier to scale: A decoder-only model is a single stack of identical blocks. There is no encoder, no cross-attention, and no separate pretraining objectives. Fewer moving parts means fewer engineering decisions as you scale to hundreds of billions of parameters.
    • Unified pretraining objective: Next-token prediction is a single, general-purpose objective that works for every type of text. Encoder-decoder models need separate objectives for the encoder, such as span corruption, and decoder, which adds complexity.
    • One architecture for all tasks: Through prompting and instruction tuning, a decoder-only model handles classification, generation, reasoning, tool use, and conversation without architectural modifications. Encoder-only models cannot generate text natively; encoder-decoder models are harder to adapt to open-ended generation.
    • Empirical scaling: At equal compute budgets, decoder-only models have consistently matched or exceeded encoder-decoder models on downstream benchmarks. Given that compute is the binding constraint, the simpler model that scales cleanly wins.
  2. When would you still choose an encoder-only or encoder-decoder model?
    • Encoder-only: When you need high-quality bidirectional representations and do not need generation. Sentence embeddings, semantic search, classification, and named entity recognition all benefit from bidirectional attention. Models like BERT and its variants remain competitive for these tasks, especially when latency or model size is constrained.
    • Encoder-decoder: When input and output are structurally different and the input should be fully encoded before generation begins. Machine translation, document summarization with a fixed source document, and speech-to-text are natural fits. T5 and Flan-T5 remain strong choices for these applications.
      That said, instruction-tuned decoder-only models are increasingly competitive even on these tasks. The gap has narrowed considerably since 2023.
  3. What is weight tying, and when is it used?
    Weight tying shares parameters between the input embedding matrix and the output projection, or language modeling head. The input embedding maps token IDs to vectors, ℝV×d, and the output head maps hidden states back to vocabulary logits, ℝd×V. With weight tying, these two matrices are transposes of each other.
    Benefits include:
    • Parameter savings: For a vocabulary of 128K tokens and a model dimension of 4096, the embedding matrix has roughly 500M parameters. Without tying, you would have two copies, around 1B parameters total. Tying cuts this in half.
    • Regularization: Forcing the input and output spaces to share the same embedding acts as an implicit constraint that can improve generalization.
      GPT-2 and T5 use weight tying. Some models, such as GPT-3, PaLM, and LLaMA, do not tie, typically when the model is large enough that the embedding parameters are a small fraction of the total.
  4. How do you count the parameters in a transformer?
    For a decoder-only transformer with L layers, model dimension d, vocabulary size V, h attention heads, and FFN inner dimension dff:
    • Embedding: V×d parameters. If weight tying is used, the output head shares these weights, so there is no additional cost. Otherwise, add another V×d.
    • Per-layer attention: Four projection matrices, WQ,WK,WV,WO, each d×d, for a total of 4d2 per layer.
    • Per-layer FFN (standard): W1 is d×dff and W2 is dff×d. With dff=4d, that is 8d2 per layer.
    • Per-layer normalization: RMSNorm has d parameters per normalization, and there are two normalizations per layer, one before attention and one before FFN. Total: 2d per layer.
      A rough total is:
      L×(4d2+8d2+2d)+V×d≈12Ld2+Vd
      For LLaMA-7B, with L=32, d=4096, and V=32000, this gives roughly:
      32×12×40962+32000×4096≈6.4B+0.13B≈6.5B
      The actual count is 6.7B because LLaMA uses SwiGLU, which has three FFN matrices instead of two, with a different expansion ratio.

Thread: The LLaMA Recipe and Model Comparisons

  1. What are the key architectural choices in LLaMA, and why has it become the reference design?
    LLaMA (Touvron et al., 2023) assembled a set of known improvements into a clean, reproducible architecture that became the template for most open-source LLMs:
    • Pre-RMSNorm: Normalize before each sublayer using RMSNorm, which is faster than LayerNorm and more stable than post-norm.
    • SwiGLU activation: Gated FFN with three weight matrices and expansion factor 83d.
    • RoPE: Rotary positional encoding applied at every layer, not just the input.
    • No bias terms: All linear layers have bias removed. This is slightly faster and empirically performs as well or better.
    • GQA: Introduced in LLaMA 2 for the 70B model only, then used in all sizes from LLaMA 3 onward.
      LLaMA became the reference design because it was fully open, including weights and training details, performant at multiple scales, from 7B to 70B, and straightforward to reproduce. Most subsequent open-source models, including Mistral, Qwen, DeepSeek, and Gemma, adopt the same core recipe with variations.
  2. How has the LLaMA architecture evolved across versions?
    • LLaMA 1 (Feb 2023): RoPE, RMSNorm, SwiGLU, and no bias. 32K vocabulary. Sizes: 7B, 13B, 33B, 65B. Trained on 1—​1.4T tokens. Context: 2K.
    • LLaMA 2 (Jul 2023): Same base architecture. GQA added to the 70B model only. Context extended to 4K. Trained on 2T tokens. Released with chat variants tuned with RLHF.
    • LLaMA 3 (Apr 2024): Vocabulary expanded to 128K tokens, improving multilingual and code tokenization. GQA in all sizes. Context: 8K. Trained on 15T+ tokens, far beyond Chinchilla-optimal ratios for inference efficiency. Sizes: 8B and 70B.
    • LLaMA 3.1 (Jul 2024): Context extended to 128K via RoPE scaling. Added a 405B size. Same core architecture.
      The progression illustrates a general trend: the base architecture stays mostly fixed while improvements come from scaling data, extending context, and refining training.
  3. How does Mistral’s architecture differ from LLaMA?
    Mistral shares the LLaMA recipe, RoPE, RMSNorm, SwiGLU, GQA, and no bias, but adds:
    • Sliding window attention: Each layer attends only to the previous 4,096 tokens instead of the full sequence. This reduces both compute and KV cache memory for long sequences.
    • Efficient context handling: The bounded KV cache allows serving long sequences without the memory scaling of full attention.
      Mixtral extends this into MoE: 8 expert FFNs per layer with top-2 routing, giving 47B total parameters but only 13B activated per token. The attention layers remain dense and shared across all tokens.
  4. How do scaling laws guide architecture sizing decisions, including depth vs. width?
    Scaling laws provide the framework for turning a compute budget into a concrete architecture.
    Chinchilla compute-optimal balance. Hoffmann et al. (2022) showed that for a fixed compute budget, there is an optimal balance between model size and training data, and that model parameters and training tokens should scale roughly equally. A 70B-parameter model should train on roughly 1.4T tokens for compute-optimal performance. Chinchilla, a 70B model, trained on 4× more data than Gopher, a 280B model, with the same compute budget, and it outperformed Gopher across benchmarks. The implication is that many early LLMs, such as GPT-3 and Gopher, were over-parameterized and under-trained.
    Post-Chinchilla over-training for inference. The recent trend has moved in the opposite direction. LLaMA 3 trains an 8B model on 15T+ tokens, far exceeding the Chinchilla-optimal ratio. The reason is inference cost: a smaller model trained for longer is much cheaper to serve than a larger model trained at the Chinchilla optimum. For production deployment, total cost of ownership, training plus inference, favors over-training smaller models.
    Depth vs. width given a budget. Scaling laws from Kaplan et al. (2020) found that performance depends primarily on the total parameter count, and that architectural details like depth-to-width ratio matter less than total scale, within a reasonable range. That said, practical considerations create preferences:
    • Depth (more layers): Adds more sequential computation steps, which can help with tasks requiring multi-step reasoning. But each additional layer adds latency to autoregressive generation, since tokens pass through every layer sequentially, and very deep models can be harder to train due to gradient issues and communication overhead in distributed settings.
    • Width (larger d): Each layer processes a richer representation, and wider models parallelize better within a single layer. But the FFN parameters scale as d2, so width increases parameter count faster.
      Most production LLMs follow established depth-to-width ratios: LLaMA-7B uses 32 layers with d=4096, while LLaMA-70B uses 80 layers with d=8192. The ratio of depth to width increases at larger scales, suggesting that depth becomes relatively more important as models grow.

Thread: Emerging Architectures

  1. What are state space models (Mamba), and how do they differ from transformers?
    State space models, or SSMs, process sequences through a recurrence that maps each input to a hidden state, similar in spirit to RNNs but with a structured state transition that can be computed efficiently.
    Mamba (Gu and Dao, 2023) is the most prominent SSM variant. Its key innovation is selective state transitions: the parameters that control how information enters and leaves the hidden state are input-dependent, allowing the model to selectively retain or discard information based on content. This gives Mamba content-aware filtering, unlike classic SSMs where the transition is fixed.
    Key differences from transformers:
    • Linear-time inference: Mamba processes a sequence in O(n) time, versus O(n2) for full self-attention, making it attractive for very long sequences.
    • Constant-size state: The hidden state has a fixed size regardless of sequence length, so there is no growing KV cache.
    • Training: Mamba uses a parallel scan algorithm for efficient training on GPUs, avoiding the sequential bottleneck of traditional RNNs.
    • Weakness: Mamba can underperform transformers on tasks requiring precise long-range recall or in-context learning, where attention’s ability to look up any past token directly is advantageous.
  2. What are hybrid architectures like Jamba?
    Jamba (AI21, 2024) alternates Mamba layers and transformer attention layers within the same model, combined with MoE for the FFN components. The idea is to get the best of both worlds:
    • Mamba layers handle the majority of sequence processing at linear cost, providing efficient long-context modeling.
    • A smaller number of attention layers are interspersed to handle tasks that require precise token-to-token lookup, such as retrieval, copying, and in-context learning.
    • MoE keeps the activated parameter count manageable while maintaining high total capacity.
      The original Jamba (v0.1) has 52B total parameters with 12B activated per forward pass. It demonstrates that hybrid SSM-attention architectures can be competitive with pure transformers while offering better efficiency at long sequence lengths.
      Mamba-2 (Dao and Gu, 2024) further strengthened the theoretical connection between SSMs and attention by establishing a “structured state space duality,” showing that certain SSM formulations are mathematically equivalent to specific attention patterns.
  3. What is multi-token prediction, and why might it improve training?
    Standard language model training predicts one token at a time: given all preceding tokens, predict the next one. Multi-token prediction trains the model to predict several future tokens instead of just the next one. Designs differ: Meta’s approach (Gloeckle et al., 2024) attaches N parallel prediction heads on a shared trunk, typically N=4 to 8, while DeepSeek-V3 uses a sequential module that predicts one additional token beyond the next.
    Potential benefits include:
    • Richer gradient signal: Each training position provides N loss signals instead of one, which can improve sample efficiency.
    • Better planning: Predicting multiple future tokens encourages the model to form representations that account for longer-range structure, not just the immediate next token.
    • Faster inference (speculative): The auxiliary prediction heads can serve as a built-in draft model for speculative decoding, generating multiple candidate tokens in parallel.
      Both Meta’s research and DeepSeek-V3 adopt multi-token prediction. Gains are most pronounced for code generation, where predicting multiple tokens helps with structural patterns like matching brackets and consistent variable names.
  4. How do architectural choices affect the KV cache at inference?
    The KV cache stores the key and value vectors from all previous tokens so they do not need to be recomputed during autoregressive generation. Its size is:
    KV cache=2×L×n×dkv×bytes per element
    where L is the number of layers, n is the sequence length, and dkv is the dimension of the key/value vectors.
    Architectural choices directly control dkv:
    • MHA: dkv=d, the full dimension. This produces the largest cache.
    • GQA: dkv=d×g/h where g is the number of KV groups and h is the number of query heads. With 8 KV groups and 32 query heads, this gives a 4× reduction.
    • MQA: dkv=d/h, a single KV head. This reduces the cache by a factor of h.
    • MLA: Compresses K and V into a low-rank latent, around a 93.3% reduction.
    • Sliding window: Caps n at the window size w, bounding the cache regardless of sequence length.
      To put this in perspective: for LLaMA-70B at 128K context in FP16, MHA would require over 300 GB of KV cache for a single sequence, while GQA brings this down to roughly 40 GB. Without architectural cache reduction, even one long-context request would not fit on available hardware.
