Chapter 2. Vision Language Model Applications

We have seen how vision and language is bridged, so let’s see how modern vision language models (VLMs) work. Modern VLMs—typically trained on massive vision, vision language, and language datasets—can accomplish a wide variety of vision tasks like identifying objects, actions, and scenes, as well as understand text for multimodal tasks. The possibilities of bridging images and text make the use cases endless, but we will focus on the most common use cases, early approaches used to solve them, how to accomplish these tasks, and how to evaluate a model on a given task.

The most natural place to start is the simplest form of connecting vision and language: describing what we see. Given an image, can a model produce a sentence that captures its content? This is image captioning, and it is the foundation on which many of the tasks in this chapter build.

Learning Objective

In this chapter, we will learn all the tasks we can accomplish with modern VLMs. In each task, we will see what the task looks like, offer model recommendations, consider previous approaches to solve the problem, evaluate a good model, and more!

Image Captioning

The first task we will see is image captioning. This task is about describing the visual content of an image in natural language​. Image captioning sits at the intersection of computer vision and natural language processing. It requires a model to understand an image (identify objects, attributes, and their relationships) and generate a coherent sentence describing the image. This task is a fundamental problem in artificial intelligence that connects vision and language​.

Early methods to solve image captioning adopted a visual encoder (typically a convolutional neural network [CNN]) that transforms the image into a feature representation. This representation was then fed to a text decoder (usually a recurrent neural network [RNN]) to generate a caption (see Figure 2-1).

Figure 2-1. Image captioning input, output, and rough model architecture.

This end-to-end approach learned to “translate” an image to a caption, treating the image as the source language and English as the target language​. During training, the long-short-term memory learns to predict the next word of actual human-written captions from the image, creating a connection between visual content and language to generate appropriate descriptions for new images.

Recent models adopt powerful visual encoders with pretrained large language models (LLMs) to improve caption generation. Many generalist VLMs can caption images in detail, as well as perform other vision-language tasks. Models like Gemma-3 by Google DeepMind and the newer Qwen3.5 by Alibaba can all generate high-quality captions out of the box.

Captioning tells us what is in an image, but what if we want to ask a specific question about it? Rather than generating a general description, we might want the model to focus on a particular aspect of the scene. This is exactly what visual question answering (VQA) enables.

Visual Question Answering

You know when you have an image and you give it to ChatGPT and ask, “Does this top work for me?” That’s a visual question! Answering such questions demands focused, accurate multimodal understanding and reasoning. It can be complex: the model has to combine and interpret image and text inputs. Imagine questions that involve counting, localizing, and comparing.

In other words, the model needs to understand how objects are arranged, understand how they might interact, and use common sense about everyday life to produce accurate responses.

Let’s look at the evolution of VQA models.

The early VQA models kept things pretty simple: they grabbed image features using CNNs and encoded questions with RNNs, then combined them with basic classifiers to predict answers. These models worked OK for simple questions like “What color is the car?” but hit a wall when faced with anything requiring deeper reasoning.

Later models employed the attention mechanism to dynamically focus on regions of interest in an image based on the question itself.

Today’s cutting-edge VQA models use transformers trained on massive image-text datasets. These models are much more impressive: they generalize well to new scenarios and can handle complex questions by bringing in outside knowledge that isn’t even in the image. They’ve learned from seeing millions of image-text pairs, developing a kind of visual common sense that earlier models simply didn’t have. As of 2026, the best open models for general VQA include Kimi K2.5 and Qwen3-VL, available in sizes from 2B to 235B parameters.

Despite these advancements, models continue to struggle with complex, multistep reasoning, abstract concepts, and “what if” cases. Often, models exploit dataset biases instead of truly understanding. Moreover, the rationale behind their answer is not transparent. Multistep conversations are even harder to solve, as models need to remember the previous turns. With ongoing research, models keep making progress toward human-like visual reasoning.

To evaluate models, you can refer to the Massive Multi-discipline Multimodal Understanding and Reasoning (MMMU) benchmark. It contains questions from college exams, quizzes, and textbooks, spanning six broad disciplines: art and design, business, science, health and medicine, humanities and social science, and tech and engineering. It contains a lot of images with lower-level details like charts, tables, infographics. An even harder benchmark is MMMU-Pro. It is built by first filtering out questions that text-only models could answer without even looking at the image, then augmenting the answer choices to make guessing harder, and finally introducing a vision-only input setting where the question itself is embedded inside the image. You can see example questions in different categories in Figure 2-2. As of early 2026, on MMMU-Pro, open models score roughly 16–27 points lower than on MMMU, showing the benchmark’s increased rigor.

Figure 2-2. MMMU benchmark, taken from the paper.

VQA models can answer direct questions about an image, but many real-world scenarios demand more than a quick answer. Sometimes the model needs to chain multiple observations together, compare details, or apply logic before arriving at a conclusion. This is where visual reasoning comes in.

Visual Reasoning

But what if our questions aren’t answered in one sentence and a simple glance from the model? Consider asking about drug interactions in the back of a pill case. In such cases, the model needs to “think” a bit before answering, just like how humans do (see Figure 2-3). Another case where thinking makes sense is calculating something over an invoice. Enter visual reasoning: a new task where the model can interpret complex relationships and reason from visual information.

The first ever working open VLM for reasoning was Kimi-VL in 2025. Many models have failed to solve this problem as reasoning happens as the model looks at the image once, and then reasoning happens in text modality. This is a relatively new field, but there are a few models such as Qwen3-VL and Kimi K2.5 in different sizes. Like LLMs, visual reasoning requires long context models that are relatively large.

You can evaluate visual reasoning models based on a variety of benchmarks depending on the task itself, such as math and logic reasoning, scientific reasoning, chart and diagram understanding, medical imaging, and computer use. Benchmarks like MathVista probe vision-math fusion over diagram. MMMU and MMMU-Pro can also be used to evaluate reasoning models as those questions require thinking. Reasoning models on GUI interactions, on the other hand, are evaluated on benchmarks like OSWorld.

Figure 2-3. Visual reasoning example.

So far we have looked at tasks where a model generates text from a single image: captions, answers, or chains of reasoning. But what happens when we are not working with just one image? In many practical settings, we have large collections of images or documents, and the challenge shifts from understanding a single image to finding the right one. This brings us to visual language retrieval.

Visual Language Retrieval

What if you cannot find an answer to a question or try to find an instance of a query from a single image or a page? In that case, we need models that can search for the answer in multiple pages and locate the answer in a page or image. Unlike generative captioning or VQA, where an answer is generated, retrieval identifies the most relevant items from existing databases to manage and search extensive image-text repositories to keep the meaning across two modalities.

Vision language retrieval models have to work on a joint image-text vector space. In this space, images and texts that are similar are closer to each other. The distance between elements in that space is measured with cosine similarity or Euclidean distance.

Retrieval is formulated as a ranking problem. Since there are text and images, we’re dealing with three situations:

Text-to-image retrieval

Images are ranked by relevance to a textual query.

Image-to-text retrieval

Textual descriptions are ranked based on their relevance to an image query.

Image-to-image retrieval

Images are ranked by relevance to an image query.

We saw an example of visual language retrieval in the end of Chapter 1, where we used a CLIP-like model to do text-to-image search. As of 2026, you can go way beyond images: you can also search through documents. Documents include finer details and nuances compared to images, so it’s a harder task. We will see this in Chapter 8.

A major breakthrough in document retrieval came with models that treat documents as images and bypass optical character recognition (OCR) entirely. ColPali, built on connecting a VLM and a large language model as dual encoder, embeds each document page as a set of visual vectors and matches them against query vectors at a fine-grained, token-level granularity. Its successor, ColQwen2, built on Qwen2-VL and Qwen2 in similar fashion, further improves accuracy with dynamic resolution support. For single-vector embedding-based retrieval, Qwen3-VL-Embedding ranked first on the MMEB-V2 multimodal embedding benchmark with a score of 77.8.

The primary benchmark for visual document retrieval is ViDoRe. ViDoRe V3 covers thousands of document pages across 10 professional domains with human-verified queries in six languages, and includes a live leaderboard for evaluating end-to-end retrieval systems.

Moreover, we evaluate retrievers using a metric called normalized discounted cumulative gain (NDCG) at cutoff k examples. It measures how well a retrieval system ranks the most relevant results at the top of the list, within the top-K results. The score is between 0 and 1, where 1.0 is a perfect ranking. Gain is just the relevance score of a single result. Before running the metric, a human (or ground-truth labels) assigns each possible result a relevance score. For example, a gain of 3 is perfect, whereas a gain of 0 is irrelevant. Cumulative means we add up the gains across all results in the list. Discounted defines that we penalize results that appear lower in the ranking. The idea is simple: position 1 is best, and position 10 is not. Concretely, the gain at position i gets divided by log₂(i + 1). At position 1, that’s log₂(2) = 1, so no penalty. At position 2, it’s log₂(3) ≈ 1.58, so you lose some value. Then we normalize all the scores to be between 0 and 1, by dividing by the best possible score (called ideal DCG), which is the score if results were sorted perfectly by relevance. Lastly, we only look at the top-K results (@k). NDCG@5 only grades positions 1 through 5. Let’s see a visual example in Figure 2-4.

Figure 2-4. NDCG@k search example.

Retrieval helps us locate the right image or page, but once we have found it, we still need to extract and interpret its contents. Documents, in particular, carry a rich mix of text, tables, charts, and layout cues that go far beyond what a typical image contains. Let’s look at how models tackle this challenge.

Document Understanding

Once we retrieve the documents and images, we need to get the actual information in them. Unlike typical photos or images, documents pack information into text, tables, charts, diagrams, and other visual elements organized in specific layouts. Enter document understanding, a more specialized task made to get answers from documents.

Traditionally, document understanding relied mainly on OCR combined with handcrafted rules to interpret layouts and content. While these OCR-based methods worked fine for simple, standardized documents, they often struggled with complex layouts, poor-quality scans, or complex visuals. Thankfully, the deep learning paradigm has dramatically improved this, offering robust, adaptable solutions that handle diverse document types and extract richer meanings, as shown in Figure 2-5.

Figure 2-5. InfoVQA example.

OCR is still a recurrent paradigm where the models are continuously challenged with hard-to-read handwritings, or transcribing complex media like infographics into meaningful information (to media like HTML or Markdown). Two outstanding benchmarks to evaluate and pick good OCR models are OmniDocBench and OlmOCRBench.

Notable open models for document OCR include GLM-OCR (only 0.9B parameters, ranks first on OmniDocBench v1.5 with a score of 94.62, MIT license), OlmOCR 2 by AllenAI, and LightOnOCR-2-1B.

Modern document understanding systems operate in hierarchical layers. They begin with recognizing text, detecting visual elements, and parsing document layouts. Then, they analyze structure by identifying components like paragraphs, tables, and figures while mapping their spatial and hierarchical relationships. Finally, these systems integrate visual and textual information to extract deeper meanings, enabling complex tasks such as question answering, summarization, and knowledge extraction.

Let’s dig into two key aspects: document retrieval and information extraction.

Document Visual Question Answering

Answering questions about documents helps extract information from them. Earlier techniques like LayoutLM used a ton of feature engineering: feeding in layouts (bounding boxes surrounding text blocks) and text from documents passed through OCR. With generalist VLMs, we no longer need to do this, but it’s useful in cases where you want to extract parts of text or documents directly instead of generating an answer. There are many tasks that can be considered under the umbrella of document question-answering depending on the media we are trying to get the answer from, such as infographics, charts, and tables. See how infographics VQA looks in Figure 2-5.

Let’s consider the current state of the art in document question answering from a stack of documents by combining multimodal retrievers and VLMs. We pass the documents and a question to the retriever to retrieve the relevant page, and then pass the question and relevant page to the VLM for the model to generate the answer. This process is called multimodal retrieval-augmented generation (RAG), and we will explore this and fine-tuning in more detail in Chapter 8.

Up to this point, every task we have discussed works with static images or documents. But the visual world is not static; it moves. Videos introduce a temporal dimension that fundamentally changes what a model needs to understand. Let’s see how VLMs handle the jump from still frames to moving sequences.

Video Understanding

When we think about it, video is “just” a collection of consecutive images. Given that we have already seen how to work with images, this now sounds easy, but it’s not! Enter the temporal (time) dimension. In any task related to video understanding, a model needs to capture temporal relationships between video frames, especially where videos have object interactions and motion. You can see an illustrated example in Figure 2-6.

Figure 2-6. Video understanding.

One typically needs to sample image frames from videos. If you sample too few images, you will lose information; if you sample too much, the video frames will carry less information than they should, and you will be wasting compute resources.

The possibilities of what you can do with videos and VLMs are endless. We will see more subtasks in Chapter 9, but here are two of them for now:

Text-to-video retrieval

Finds relevant video content based on text prompts. Modern text-to-video retrievers are CLIP-like models with encoders for both video and text and are trained on narrated video clips.

Temporal grounding

Picks specific timestamps within videos for given text prompts. This allows users to pinpoint exact moments in videos using text prompts rather than watching videos.

Many recently released generalist VLMs, like Qwen3-VL and Qwen3.5, are good in general video understanding. Although there have been many models that were specifically trained for video understanding, temporal grounding and instance tracking in videos still remains a challenge. Specialized systems like SAGE by AllenAI tackle long video reasoning with an agent-based approach: rather than processing an entire video in one pass, SAGE iteratively reasons over video segments, mimicking how humans scrub through footage. Molmo2 (also by AllenAI) achieves state-of-the-art video pointing (38.4 F1, outperforming Gemini 3 Pro at 20.0) and video tracking using only 9.19M training videos.

Video models are typically evaluated on three tasks: general video understanding, long video understanding, and temporal grounding. VideoMME is a benchmark for general video understanding, and it contains short, medium, and long videos (two minutes to one hour). Meanwhile, LVBench is used for long video understanding, and TemporalBench is used for temporal reasoning in the videos.

All the tasks we have explored so far produce text as output: captions, answers, reasoning chains, or retrieved results. But many applications need the model to point at specific regions in an image rather than just talk about them. Object detection, counting, and segmentation require the model to output spatial coordinates or masks, bridging language with precise localization.

Instance Localization with Vision Language Models

The last task we will see in the world of vision language is instance localization (or traditional computer vision tasks). Traditional computer vision models require training on a fixed set of objects to detect or segment objects, which requires expertise. Modern VLMs lower the barrier of entry to computer vision: these models are generalist, they don’t require training on a specific task, and they can take text input to identify, detect, and segment objects in images. We will now go through instance localization applications, including zero-shot object detection and image-guided detection, and show how to infer with the existing set of models.

Zero-Shot Object Detection

The first subtask in open-ended instance localization is zero-shot object detection. Zero-shot object detection detects objects from open-ended text prompts, as shown in Figure 2-7.

Figure 2-7. Zero-shot object detection.

OWLv2 and GroundingDINO are the two noteworthy open source models specifically trained for this task, but one can also use generalist VLMs that take prompts like “detect the bee.” OWLv2, released by Google, uses a vision encoder combined with a text encoder similar to CLIP to detect bounding boxes through text prompts. The vision encoder is followed by a simple linear layer to detect the bounding boxes with their labels. GroundingDINO is very similar to OWLv2; it has an image encoder and a text encoder, with feature enhancer modules after them. These models can only take a set of open-ended objects (e.g., bee on the pink flower) and return the bounding boxes. Unlike generalist VLMs, they are incapable of doing any other task. Generalist VLMs, on the other hand, return bounding box coordinates with generated output tokens in x, y, w, h format where x, y are the top-left corner and w, h are width and height.

VLMs in zero-shot object detection are practically less cost-efficient to run in production than their pure computer vision peers. Nevertheless, VLMs are great to create training datasets for vision models: they are often used in automatic bounding box annotation for training of smaller object detectors. For instance, imagine you have images of a production line where you have bottles with metal and plastic caps and you need to detect only the plastic ones. You can ask a generalist model to only label the plastic caps and then train an object detection model, which will learn to ignore the metal caps and only detect plastic.

Another challenge with working with zero-shot object detectors is filtering for their results. These models take a confidence threshold input used to filter out incorrect bounding boxes. There is no free lunch when picking confidence thresholds; they depend on how fine-grained the task is, and you need to play with different thresholds to determine one for your use case. A good pointer in where to begin is often given in model cards or papers of the models.

To use OWLv2 through UI, see the example from Hugging Face, which is featured in Figure 2-8.

Figure 2-8. OWLv2 demo.

Object Counting

If we can detect objects through descriptions or visual references, can we count them accurately? Intuitively, counting should be as simple as tallying the bounding boxes of detected objects. Many modern VLMs like Molmo2 by AllenAI point to or detect objects and then count the instances. Moreover, Molmo2 can not only do this in images but also can point to each object instance and track them in videos, and this way, it can even count in videos accurately. You can try Molmo2 in this demo, and you can see an example in Figure 2-9.

Image Segmentation

The last task we can accomplish with VLMs is image segmentation from open-ended text prompts. In training generalist models, the key distinction between models is how they decode the output segmentation masks. Moondream2 outputs segmentation masks as SVG polygons, like the following:

{ "path": "M 0 0.76 L 0 0.32 L 0.03 0.31 C …", "bbox": { "x_min": 0.0002, "y_min": 0.0039, "x_max": 0.7838, "y_max": 0.9971 } }

Meanwhile PaliGemma2 by Google DeepMind takes a more complex approach. The model takes in localization prompts such as “segment bird; plant” or “detect cat” and outputs normalized bounding box tokens for detection (e.g., ) and codebook indices for segmentation (). These tokens then go into a variational autoencoder that decodes them into segmentation masks. You can see the process in Figure 2-10.

Summary

This chapter has given you a glimpse into the applied world of VLMs. Knowing what is possible, what types of models there are, each task you can accomplish, and how to pick a model for each task will help you employ them for real-world cases. We have introduced recent models here, and although the paradigm changes fast and many models come out, playing with an existing set of models right away and checking benchmarks will help you adapt to current state of the art. In the upcoming chapters, we will see these tasks in depth and learn how to customize models for each and how to deploy. Let’s go!
