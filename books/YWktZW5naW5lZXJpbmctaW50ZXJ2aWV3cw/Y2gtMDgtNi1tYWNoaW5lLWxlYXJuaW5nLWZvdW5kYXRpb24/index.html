Chapter 6. Machine Learning Foundation

Before an LLM can generate a single word, it must learn from data. That learning process is called machine learning. Every component of a modern language model, from the neurons that detect patterns to the optimizer that adjusts billions of weights, rests on machine learning foundations that have been refined over decades.

This chapter covers the building blocks that power LLMs: how neural networks are structured, how different learning paradigms produce different kinds of models, how loss functions guide training, and how optimization algorithms help models converge. For readers who want a deeper review of the mathematical foundations (such as derivatives, probability distributions, and linear algebra) we provide supplementary material in our GitHub repository: https://aiengineeringinterviews.github.io/. That material explains the underlying “why,” while this chapter focuses on the “how” through architectures, algorithms, and practical techniques.

From Neurons to Deep Networks

The simplest neural network component is a single neuron (also called a unit or perceptron). A neuron takes an input vector 𝐱, computes a weighted sum, adds a bias, applies an activation function, and generates an output vector 𝐲:

y=σ(𝐰·𝐱+b)

Here 𝐰 is a vector of learnable weights, b is a learnable bias, and σ is an activation function (such as ReLU, GELU, sigmoid, etc.). The weights determine which inputs the neuron pays attention to, and the activation function introduces non-linearity.

Stacking multiple neurons side by side creates a layer: each neuron in the layer receives the same inputs but has its own weights, producing its own output. A layer with 𝐦 neurons transforms an input 𝐱∈ℝn into an output 𝐲∈ℝm. Mathematically, this is a matrix multiplication followed by an activation:

𝐲=σ(𝐖𝐱+𝐛)

where 𝐖∈ℝm×n is the weight matrix in which each row is one neuron’s weights.

Stacking layers on top of each other creates a deep neural network. The output of one layer becomes the input to the next layer:

f(𝐱)=fL(…f2(f1(𝐱)))

Depth is what gives neural networks their power. Each layer transforms the representation and extracts increasingly abstract features. In an LLM, early layers capture token-level patterns (syntax, common phrases), while later layers capture high-level semantics (meaning, reasoning).

Figure 6-1 illustrates this progression from a single neuron to a deep network.

Universal Approximation

The universal approximation theorem states that a neural network with at least one hidden layer and a non-linear activation function can approximate any continuous function to arbitrary accuracy, given enough neurons. In practice, depth is more efficient than width: a deep network with modest-width layers can represent functions that would require exponentially many neurons in a shallow network. This is why modern LLMs are deep (32 to 128 layers) rather than wide.

Layer Types in Transformers

A transformer-based LLM uses several types of layers:

  • Embedding layer maps discrete token IDs to continuous vectors.

  • Attention layer computes self-attention and allows each token to attend to all previous tokens.

  • Feed-forward network (FFN) is a two-layer MLP applied independently to each token position. FFN layer typically expands the dimension by 4×, applies an activation function, and projects back down to the dimension of the model.

  • Normalization layer stabilizes training by normalizing activations. Transformers use layer normalization, not batch normalization (explained in ?).

  • Output projection maps the final hidden states to logits over the vocabulary. In many models, it reuses the input embedding matrix rather than learning a separate output matrix, a technique known as weight tying or tied embeddings.

Activation Functions

Without activation functions, stacking any number of linear layers would produce another linear transformation: 𝐖2(𝐖1𝐱)=(𝐖2𝐖1)𝐱. The non-linearity is what allows neural networks to learn complex patterns. The choice of activation function affects training stability, gradient flow, and model performance.

Figure 6-2 compares the most common activation functions.

ReLU (Rectified Linear Unit) is defined as ReLU(x)=max(0,x). It is simple, computationally efficient, and widely used in neural networks. For positive inputs, its gradient is 1, which helps preserve gradients during training and reduces the vanishing-gradient problem associated with sigmoid and tanh. For negative inputs, however, both the output and gradient are 0. This can lead to the dying ReLU problem: if a neuron consistently receives negative inputs, it may stop updating and no longer contribute to learning. Variants such as Leaky ReLU address this issue by retaining a small nonzero slope for negative inputs, for example max(0.01x,x).

GELU (Gaussian Error Linear Unit) is defined as GELU(x)=x·Φ(x), where Φ(x) is the cumulative distribution function of the standard Gaussian distribution. Unlike ReLU, which applies a hard cutoff at zero, GELU smoothly scales each input based on its magnitude. Large positive values pass through almost unchanged, while negative and small positive values are gradually suppressed. This smooth behavior supports stable optimization and has made GELU a common activation function in transformer models, including BERT and many GPT-style architectures.

SiLU / Swish is defined as SiLU(x)=x·σ(x), where σ is the sigmoid function. Like GELU, SiLU is smooth and self-gated: the sigmoid term controls how much of the input passes through. SiLU is used in LLaMA, PaLM, and other recent LLMs. In practice, GELU and SiLU often achieve similar performance, and the choice depends on the model architecture and empirical results.

Sigmoid is defined as σ(x)=1/(1+e−x) and maps its input to a value between 0 and 1. For inputs with large positive or negative values, the function saturates and its gradient approaches zero, which can contribute to the vanishing-gradient problem. For this reason, sigmoid is rarely used as a hidden-layer activation in modern LLMs. It remains useful in gating mechanisms, where its output controls how much information is allowed to pass through.

Tanh The hyperbolic tangent function, tanh(x), maps its input to a value between -1 and 1. Unlike sigmoid, its outputs are centered around zero, which can make optimization easier in some settings. However, tanh also saturates for inputs with large magnitudes, causing its gradient to approach zero and contributing to the vanishing-gradient problem. For this reason, it is rarely used as a hidden-layer activation in modern LLMs, though it still appears in recurrent networks and components that require bounded outputs.

Softmax. Softmax is not a typical activation function but rather a normalization function that converts a vector of scores into a probability distribution. It is used at the output layer to produce token probabilities and inside the attention mechanism to normalize attention scores. Softmax is covered in detail in the Math section in the book’s GitHub repository https://aiengineeringinterviews.github.io/.

Learning Paradigms

Machine learning models learn in fundamentally different ways depending on the type of supervision they receive. Figure 6-3 shows the four main paradigms and their role in LLM development.

Supervised Learning. In supervised learning, the model trains on labeled data: each input has a known correct output. The model learns to map inputs to outputs by minimizing a loss function (e.g., cross-entropy for classification, MSE for regression). Supervised learning requires large, well-labeled datasets, which can be expensive to create.

For LLMs, supervised learning appears in supervised fine-tuning (SFT). After pretraining, the model is fine-tuned on curated (prompt, response) pairs from human annotators. SFT teaches the model to follow instructions and produce helpful, formatted responses.

Unsupervised Learning. In unsupervised learning, the model discovers patterns in data without labels. Clustering (grouping similar items), dimensionality reduction (compressing high-dimensional data), and density estimation (modeling the data distribution) are classic unsupervised tasks. While not directly used in LLM training, unsupervised techniques appear in preprocessing such as in topic modeling, and data clustering for curriculum learning.

Self-Supervised Learning. Self-supervised learning generates training labels from the data itself. This is the paradigm for LLM pretraining, and its success is what makes modern LLMs possible. There are three common self-supervised learning objectives:

  • Causal language modeling (GPT-style): This objective predicts the next token from the tokens that come before it. The label is simply the next token in the text. Every position in every document provides a training example, yielding trillions of examples from web-scale data. This is the dominant pretraining objective for modern LLMs.

  • Masked language modeling (BERT-style): This objective randomly masks some tokens in the input and predict them from the surrounding context. This produces bidirectional representations, allowing each token to attend to both the left and right context. It is well suited to language-understanding tasks but does not generate text autoregressively.

  • Contrastive learning: This objective learns representations by pulling similar examples closer together and pushing dissimilar examples farther apart in embedding space. It is used in sentence-embedding methods such as SimCSE (Gao et al., 2021) and Sentence-BERT (Reimers and Gurevych, 2019).

Reinforcement Learning (RL). In reinforcement learning, a model takes actions in an environment, receives rewards, and learns through trial and error to maximize its cumulative reward (Sutton and Barto, 2018). For LLMs, RL is commonly used during alignment to encourage outputs that better reflect human preferences or specified objectives (Ouyang et al., 2022). Reinforcement Learning from Human Feedback (RLHF) often uses algorithms such as Proximal Policy Optimization (PPO) (Schulman et al., 2017), while newer approaches may use Group Relative Policy Optimization (GRPO) (Shao et al., 2024).

When asked “how are LLMs trained?” the answer is a three-stage pipeline: (1) self-supervised pretraining (causal language modeling on web text), (2) supervised fine-tuning (SFT on curated instruction-response pairs), and (3) reinforcement learning from human feedback (RLHF for alignment). Know which learning paradigm applies at each stage.

Loss Functions

A loss function measures the gap between the model’s prediction and the desired output. Training minimizes this gap by adjusting the model’s parameters. The choice of loss function determines what the model learns to optimize. Common loss functions include:

Cross-Entropy Loss. For an LLM predicting the next token, the loss at each position is:

ℒt=−logPθ(xt∣x<t)

where Pθ(xt∣x<t) is the probability the model assigns to the correct token xt, given all preceding tokens. Assigning a higher probability to the correct token produces a lower loss. The total training loss is the average over all positions:

ℒ=−1T∑t=1TlogPθ(xt∣x<t)

Cross-entropy loss is the standard for LLM pretraining and fine-tuning. As discussed in the book’s GitHub repository https://aiengineeringinterviews.github.io/, minimizing cross-entropy is equivalent to maximum likelihood estimation: it pushes the model to assign high probability to the tokens that actually appear in the training data.

Perplexity. Perplexity is the exponential of the average cross-entropy loss:

PPL=exp(−1T∑t=1TlogPθ(xt∣x<t))

Intuitively, perplexity measures “how many tokens is the model choosing between” at each step. A perplexity of 10 means the model is, on average, as uncertain as if it were choosing uniformly among 10 tokens. Lower perplexity indicates better predictions. State-of-the-art LLMs achieve single-digit perplexity on standard benchmarks.

Contrastive Loss. Contrastive loss trains models to produce similar embeddings for similar inputs and dissimilar embeddings for dissimilar inputs. A common formulation is:

ℒ=−logexp(sim(𝐳i,𝐳j)/τ)∑kexp(sim(𝐳i,𝐳k)/τ)

where sim is a similarity function, typically cosine similarity; (𝐳i,𝐳j) is a positive pair of related examples; and τ is a temperature parameter. Contrastive objectives are widely used in embedding models, including Sentence-BERT (Reimers and Gurevych, 2019) and CLIP (Radford et al., 2021), as well as in self-supervised representation learning.

KL (Kullback–Leibler divergence) divergence: measures how different two probability distributions are. In RLHF, it is used as a regularizer to discourags the policy from drifting too far from the reference model.

Reconstruction losses (L1/MSE): measure the difference between an original input and its reconstruction. They are commonly used in autoencoders, diffusion models, and image-generation systems, but are not central to text-based LLM training.

Reward-based losses: in RLHF, the objective is to maximize the expected reward from a reward model while staying close to the reference policy. The Proximal Policy Optimization (PPO) clipped objective (Schulman et al., 2017) and Direct Preference Optimization (DPO) loss (Rafailov et al., 2023) are specific formulations of this category that are covered in Chapter 11.

Optimization and Training Stability

Optimization algorithms adjust model parameters to minimize the loss function. The choice of optimizer, learning rate, and schedule directly affects whether training converges, how fast it converges, and how well the final model generalizes.

Before any optimizer can take a step, it needs the gradient of the loss with respect to every parameter. Backpropagation is the algorithm that computes those gradients efficiently: it applies the chain rule layer by layer, starting from the loss at the output and propagating partial derivatives backward through the network, reusing intermediate results so the whole pass costs about as much as one forward pass. The optimizers below all assume this gradient is already available; backpropagation is what produces it. The supplementary mathematics material in our GitHub repository derives the chain-rule mechanics in detail: https://aiengineeringinterviews.github.io/.

Figure 6-4 shows the evolution from basic gradient descent to modern optimizers. Next, we cover the core optimization methods and training techniques.

Gradient Descent. The foundation of neural network training is gradient descent. It updates the model’s parameters in the direction opposite the gradient, where the loss decreases:

θt+1=θt−α∇θℒ(θt)

Here,θt represents the model parameters at training step t, α is the learning rate, and ∇θℒ(θt) is the gradient of the loss with respect to the parameters.

Computing the gradient over the entire training dataset is called batch gradient descent. It produces an exact gradient for the full dataset, but is computationally impractical for large-scale training with billions or trillions of tokens.

Stochastic and Mini-Batch Gradient Descent. Stochastic gradient descent (SGD) computes each update from a single training example, making updates fast but highly noisy. Mini-batch gradient descent computes the gradient from a small group of examples (e.g., 32 to 4096 examples), providing a more stable estimate while remaining computationally efficient. In practice, LLMs are trained using mini-batches rather than the entire dataset at once.

Batch size affects training dynamics. Larger batches produce smoother, lower-variance gradient estimates but require more memory. Smaller batches introduce noise, which can help the optimizer explore the loss landscape and may improve generalization. Modern LLM training often uses large effective batch sizes by accumulating gradients across several mini-batches before updating the parameters.

Momentum. Plain SGD can oscillate in narrow valleys and crawl along flat regions. Momentum adds a velocity term that accumulates past gradients:

𝐯t=β𝐯t−1+∇θℒ,θt+1=θt−α𝐯t

Here,𝐯t is the velocity at step t, β controls how much of the previous velocity is retained, α is the learning rate, and ∇θℒ(θt) is the current gradient. A typical value for β is 0.9.

Think of a ball rolling downhill: momentum keeps the optimizer moving in the overall downhill direction even when individual gradients point in slightly different directions.

Adam. Adam (Adaptive Moment Estimation) combines momentum with per-parameter adaptive learning rates. It maintains two running averages:

  • First moment 𝐦t (mean of gradients): like momentum, smooths the gradient direction.

  • Second moment 𝐯t (mean of squared gradients): it estimates the variance and scales the update for each parameter.

The bias-corrected update rule is:

θt+1=θt−α𝐦^t𝐯^t+ϵ

Here, 𝐦^t and 𝐯^t are the bias-corrected first and second moments, α is the learning rate, and ϵ is a small constant that prevents division by zero.

Adam adapts the learning rate per parameter, which is especially important for LLMs where different parameters (embedding layers vs. attention weights vs. feed-forward weights) may need very different learning rates.

AdamW. AdamW fixes a subtle issue in Adam’s implementation of weight decay. In standard Adam, weight decay is intertwined with the gradient update, which means the adaptive learning rate modifies the decay rate for each parameter. AdamW decouples weight decay from the gradient update:

θt+1=(1−λ)θt−α𝐦^t𝐯^t+ϵ

where λ is the weight decay rate. This seemingly small change improves generalization significantly and is why AdamW has become the standard optimizer for LLM pretraining.

AdamW is a widely used optimizer for LLM pretraining. Newer optimizers such as Lion, Sophia, and Muon aim to match or beat AdamW with less memory or faster convergence, and some recent large training runs have begun adopting them. AdamW is still the safe, well-understood baseline that most pretraining recipes reach for first.

Learning Rate Schedules. A fixed learning rate is rarely optimal. Modern LLM training uses a schedule with two phases:

  • Warmup: the learning rate starts at zero (or near-zero) and increases linearly over the first few thousand steps. This prevents large, random updates early in training when the model’s initial weights produce noisy gradients.

  • Decay: after warmup, the learning rate decreases following a cosine curve, gradually shrinking to near-zero by the end of training. This allows fine-grained convergence in later stages.

The typical schedule is to have a linear warmup for 1—​5% of total steps, then have a cosine decay to a minimum learning rate (often 10× smaller than the peak).

Gradient Clipping. Even with good optimizers, gradients can occasionally spike (due to unusual data batches or numerical issues). Gradient clipping caps the gradient norm:

if ‖∇θℒ‖2>c,∇←∇·c‖∇‖2

wherec is the maximum norm, commonly set to 1.0. This prevents any single update from being catastrophically large, stabilizing training. Nearly all LLM training pipelines include gradient clipping.

Weight Initialization. How weights are initialized before training starts matters. If weights are too large, activations and gradients explode. If they are too small, they vanish. Common weight initialization strategies include:

  • Xavier/Glorot: weights are sampled according to𝒩(0,2/(nin+nout)). This initialization is commonly associated with symmetric activations such as for sigmoid/tanh.

  • He initialization: weights are sampled according to 𝒩(0,2/nin). It is designed for ReLU-like activations, and compensates for the fact that these activations zeroe out half of their inputs.

Modern transformer implementations often use scaled initialization where the variance is reduced by a factor of 1/L in residual branches, where L is the number of layers. This prevents the residual sum from growing too large in deep networks.

Normalization Layers. Normalization layers improve training stability by keeping activation magnitudes well controlled. There are two types: batch normalization and layer normalization.

Batch normalization (BatchNorm) normalizes each feature using statistics computed across examples in the mini-batch:

xi,j−μjσj2+ϵ,

where μj and σj2 are the batch mean and variance for feature j. During inference, BatchNorm typically uses running estimates accumulated during training rather than statistics from the current batch.

BatchNorm works well in many convolutional networks, but it is poorly suited to LLMs for several reasons including (1) it depends on batch statistics, which makes inference behavior differ from training, and (2) sequences in a batch have different lengths, making batch statistics unreliable.

Layer normalization (LayerNorm) by contrast, normalizes each token independently across its feature dimension:

xi,j−μiσi2+ϵ,

where μi and σi2 are computed across the hidden features of token i. Because LayerNorm does not depend on other examples or tokens, it behaves consistently across batch sizes and sequence lengths, making it well suited to transformers.

In LLMs, LayerNorm can apply either before or after each attention or feed-forward sublayer, referred to as Pre-LayerNorm and Post-LayerNorm, respectively. Most modern LLMs use Pre-LayerNorm because it generally improves optimization stability and gradient flow. We discuss these architectural variants in detail in “Residual Connection and Layer Normalization”.

RMSNorm is a simplified alternative to LayerNorm that normalizes activations using only their root mean square, without subtracting the mean. It is computationally simpler and is used in LLaMA and many other modern LLM architectures.

Regularization and Generalization

A model that memorizes training data perfectly but fails on new data is useless. Regularization techniques push the model toward simpler solutions that generalize better to unseen data. Before examining specific regularization techniques, it is useful to understand the failure modes they are intended to prevent: overfitting and underfitting.

Overfitting vs. Underfitting. Overfitting occurs when the model learns noise and idiosyncrasies in the training data rather than general patterns. It shows up as a gap between training performance (high) and validation performance (low). Underfitting occurs when the model is too simple to capture the underlying patterns, performing poorly on both training and validation data.

For modern LLMs, overfitting in the classical sense is less common than you might expect. These models are trained on trillions of tokens, often for less than one full pass through the data (less than one epoch). The sheer scale of data provides its own regularization. The more relevant concern is memorization: the model might reproduce specific training examples verbatim, raising privacy and copyright concerns.

Dropout. Dropout is a regularization technique that is used during training. It randomly sets a fraction p (e.g., p=0.1) of neuron outputs to zero. This forces the network to learn redundant, distributed representations rather than relying on any single neuron. At inference time, dropout is turned off, and activations are scaled by (1−p) to compensate (or equivalently, training activations are scaled by 1/(1−p)). Dropout is used in some transformer models but has been dropped by many recent LLMs in favor of other regularization techniques.

Weight Decay. Weight decay is another regularization technique that adds a penalty proportional to the magnitude of the weights to the loss:

ℒtotal=ℒdata+λ2‖θ‖22

Here, ℒdata is the original loss computed from the training data, θ denotes the model parameters, and the coefficient λ controls the strength of the regularization: a larger value places a stronger penalty on large weights. This encourages smaller weights, which correspond to simpler functions. Typical values are λ=0.01 to 0.1. In AdamW, weight decay is applied directly to the weights.

Early Stopping. Early stopping technique monitors the validation loss during training. If it starts increasing while the training loss continues to decrease, the model is beginning to overfit. Early stopping halts training at the point of lowest validation loss. In LLM pretraining, this is less commonly used because training runs are carefully budgeted in advance (using scaling laws to predict the optimal number of tokens), but it is common in fine-tuning.

Note

Modern LLM pretraining is often described as “compute-optimal”: given a fixed compute budget, scaling laws (like the Chinchilla scaling law) determine the optimal trade-off between model size and number of training tokens. The model is typically neither overfitting nor underfitting but rather making the best use of its compute budget. Regularization concerns become more important during fine-tuning, where the dataset is much smaller.

Summary

In this chapter, we introduced the machine learning foundations behind modern LLMs. We started with the basic building blocks of neural networks: neurons, layers, activation functions, and deep architectures. We then discussed the major learning paradigms used in LLM development, including self-supervised pretraining, supervised fine-tuning, and reinforcement learning for alignment.

We also covered the loss functions that guide training, especially cross-entropy loss and perplexity for language modeling, along with contrastive and reward-based objectives used in related settings. From there, we looked at optimization techniques such as gradient descent, momentum, Adam, AdamW, learning rate schedules, gradient clipping, initialization, and normalization.

Finally, we discussed regularization and generalization, including overfitting, dropout, weight decay, early stopping, and why memorization is often a bigger concern than classical overfitting in large-scale LLM pretraining.

Interview Questions and Answers

Thread: Neural Network Architecture

  1. What is the use of activation functions, and which ones do modern LLMs use?

    Activation functions serve a critical purpose: they introduce non-linearity. Without them, a neural network of any depth would simply compute 𝐲=𝐖L⋯𝐖2𝐖1𝐱, which is equivalent to a single matrix multiplication. Non-linearity allows the network to learn curved decision boundaries and complex patterns.

    The evolution of activation functions mirrors the progress of deep learning:

    • Sigmoid (σ(x)=1/(1+e−x)): maps to [0,1]. Historically popular but causes vanishing gradients because its maximum derivative is only 0.25. After several layers, gradients shrink exponentially.

    • Tanh (tanh(x)): maps to [−1,1]. Centered around zero (unlike sigmoid), but still saturates for large inputs.

    • ReLU (max(0,x)): revolutionized deep learning. Gradient is exactly 1 for positive inputs (no vanishing gradient) and exactly 0 for negative inputs. Fast to compute. The downside is “dying ReLU”: a neuron stuck in the negative regime never recovers because its gradient is zero.

    • GELU (x·Φ(x)): smooth approximation of ReLU, used in GPT and BERT. Provides non-zero gradients almost everywhere, avoiding the dying neuron problem.

    • SiLU/Swish (x·σ(x)): similar to GELU, used in LLaMA, PaLM, and Mistral. Self-gated: the sigmoid term smoothly controls how much of the input passes through.

    Modern LLMs overwhelmingly use GELU or SiLU. In interviews, know why the field moved away from ReLU (dying neurons, hard threshold) and toward smooth activations (better gradient flow, smoother optimization landscape).

  2. How does stacking layers create a deep network, and what does the universal approximation theorem tell us?

    A deep network is a composition of layer functions: f(𝐱)=fL(…f2(f1(𝐱))). Each layer transforms its input into a new representation, and the composition of many such transformations can express extremely complex functions.

    The universal approximation theorem (Cybenko, 1989; Hornik, 1991) says that a neural network with even a single hidden layer and a non-linear activation can approximate any continuous function on a compact domain to arbitrary precision, given enough hidden neurons. This is a powerful theoretical guarantee: it means neural networks are flexible enough to represent any pattern in the data.

    However, the theorem says nothing about efficiency. A single wide layer might need exponentially many neurons to represent functions that a deep narrow network can represent with far fewer parameters. This is why depth matters:

    • Each layer can build on the abstractions learned by the layer before it. Layer 1 might learn word-level features, layer 10 might learn phrase-level patterns, and layer 50 might capture complex semantic relationships.

    • Depth enables hierarchical feature extraction: simple features compose into complex ones. A 70-billion-parameter model spread across 80 layers is far more capable than the same number of parameters in a single layer.

    In practice, very deep networks require careful engineering (residual connections, normalization, proper initialization) to train successfully. These techniques, covered in the optimization section, are what make 100+ layer transformer training feasible.

  3. What types of layers appear in a transformer-based LLM?

    A transformer block contains several layer types, each with a specific role:

    1. Embedding layer. Converts token IDs (integers) into dense vectors. Implemented as a lookup table: the embedding matrix 𝐄∈ℝV×d stores one d-dimensional vector per vocabulary token. No matrix multiplication needed; it is pure indexing.

    2. Positional encoding/embedding. Since self-attention has no inherent notion of token order, position information must be injected. Learned positional embeddings add a position-dependent vector. Rotary Position Embedding (RoPE) applies a rotation to the query and key vectors based on their position, which generalizes better to unseen sequence lengths.

    3. Multi-head self-attention. Projects input into Q, K, V, computes scaled dot-product attention, and produces context-aware representations. Multi-head attention runs H parallel attention computations (“heads”) with different learned projections, then concatenates and projects the results. This allows the model to attend to different types of relationships simultaneously.

    4. Feed-forward network (FFN). A two-layer MLP applied independently to each token: FFN(𝐱)=𝐖2σ(𝐖1𝐱+𝐛1)+𝐛2. The first layer expands the dimension (typically to 4d), the activation introduces non-linearity, and the second layer projects back to d. The FFN is where much of the model’s “knowledge” is believed to be stored.

    5. Layer normalization. Applied before each sub-layer (pre-norm) in modern architectures. Normalizes the hidden state to have zero mean and unit variance across the feature dimension, stabilizing training.

    6. Residual connections. The output of each sub-layer is added to its input: 𝐱out=𝐱in+sublayer(𝐱in). This provides a gradient shortcut and allows each layer to learn a “correction” to the previous representation rather than computing the full representation from scratch.

    7. Output projection (“LM head”). Maps the final hidden state to vocabulary-sized logits: 𝐳=𝐖vocab𝐡. Often uses tied weights (𝐖vocab=𝐄⊤) to share parameters with the embedding layer.

  4. What is the difference between batch normalization and layer normalization, and why do transformers use layer norm?

    Both normalize activations to stabilize training, but they normalize along different dimensions:

    Batch normalization (BatchNorm) normalizes across the batch dimension: for each feature, compute the mean and variance over all examples in the mini-batch. This works well for CNNs with fixed-size inputs, but it has problems for transformers:

    • It depends on batch statistics, so behavior differs between training (batch stats) and inference (running stats).

    • Sequences in a batch have different lengths, making batch-level statistics unreliable.

    • Small batch sizes (common in LLM training due to memory constraints) produce noisy statistics.

      Layer normalization (LayerNorm) normalizes across the feature dimension: for each individual token, compute the mean and variance over all features (the d dimensions of the embedding). For a hidden vector 𝐡∈ℝd:

      LayerNorm(𝐡)=γ⊙𝐡−μσ2+ϵ+β

      where μ and σ2 are the mean and variance of 𝐡, and γ,β are learnable scale and shift parameters. LayerNorm is independent of batch size and sequence length, making it ideal for transformers.

      RMSNorm simplifies LayerNorm by removing the mean-centering step: RMSNorm(𝐡)=γ⊙𝐡/RMS(𝐡), where RMS(𝐡)=1d∑ihi2. LLaMA and other efficient models use RMSNorm because it is faster (one less reduction operation) and performs comparably.

    Pre-norm vs. post-norm: original Transformer (Vaswani et al., 2017) applied LayerNorm after each sub-layer (post-norm). Modern LLMs apply it before (pre-norm): output=𝐱+sublayer(LayerNorm(𝐱)). Pre-norm produces better gradient flow and more stable training, especially for deep networks.

Thread: Learning Paradigms

  1. What are the main types of machine learning, and which ones matter for LLMs?

    There are four main paradigms:

    Supervised learning: models train on labeled (input, output) pairs. The model minimizes the error between its predictions and the known labels. For LLMs, supervised learning appears during supervised fine-tuning (SFT), where the model is trained on curated (instruction, response) pairs written by human annotators.

    Unsupervised learning: models find patterns in unlabeled data. Clustering, dimensionality reduction, and density estimation are classic examples. While not directly used in LLM training, unsupervised techniques appear in data preprocessing (e.g., clustering data for curriculum learning, topic modeling for dataset analysis).

    Self-supervised learning: models generate their own labels from the data. This is the dominant paradigm for LLM pretraining. Causal language modeling (predicting the next token) is self-supervised because the “label” at each position is just the next token in the actual text. No human annotation is needed, which enables training on trillions of tokens of web-scale data.

    Reinforcement learning: models learn from reward signals rather than direct labels. For LLMs, RL is used in alignment (RLHF/RLAIF), where a reward model (trained on human preferences) provides feedback on the quality of model outputs.

    The three-stage LLM pipeline maps directly to these paradigms: self-supervised pretraining → supervised fine-tuning → reinforcement learning alignment.

  2. Related to self-supervised learning, how does causal language modeling work as a self-supervised objective?

    In causal language modeling (CLM), the model is trained to predict each token given all the tokens that came before it. Given a training sequence x1,x2,…,xT, the model predicts P(xt∣x1,…,xt−1) for every position t.

    The “self-supervised” part is that the labels are free: the “correct answer” at position t is simply xt, the actual next token in the text. Every position in every training document provides a training example. A single 1,000-token document yields 999 prediction tasks.

    The loss is the average cross-entropy:

    ℒ=−1T∑t=1TlogPθ(xt∣x<t)

    During training, a causal mask ensures that position t can only see tokens x1,…,xt−1 (never future tokens). This matches inference behavior, where the model generates one token at a time without access to the future.

    CLM is the objective used by GPT, LLaMA, Mistral, Gemma, and nearly all modern generative LLMs. Its advantage is simplicity and scalability: you can train on arbitrary text without any labeling, and the model simultaneously learns grammar, facts, reasoning patterns, and writing style from the same objective.

  3. How does masked language modeling differ, and when is it used?

    Masked language modeling (MLM) randomly masks a fraction (typically 15%) of tokens in the input and trains the model to predict them from the surrounding context (both left and right). The loss is computed only on masked positions:

    ℒMLM=−∑t∈maskedlogPθ(xt∣xunmasked)

    The key difference from CLM: MLM produces bidirectional representations because each masked token can attend to tokens on both sides. CLM produces unidirectional representations because each token can only see what came before.

    MLM is the pretraining objective for BERT, RoBERTa, and encoder-style models. These models excel at understanding tasks (classification, NER, question answering) where you have the full input and need to extract information. However, MLM-trained models cannot generate text autoregressively because they were never trained to predict sequentially from left to right.

    In the LLM landscape, CLM has largely won for generative models because:

    • CLM aligns naturally with text generation (predict left-to-right).

    • CLM scales better: every token is a training signal, while MLM only trains on 15% of tokens per example.

    • With enough scale, CLM-trained models develop strong understanding abilities too, making dedicated encoder models less necessary.

  4. Where does reinforcement learning fit into the LLM training pipeline?

    Reinforcement learning (RL) is used in the alignment stage, after pretraining and supervised fine-tuning. The goal is to make the model’s outputs align with human preferences: helpful, honest, and harmless.

    The standard pipeline is Reinforcement Learning from Human Feedback (RLHF):

    Step 1: Train a reward model. Collect pairs of model responses to the same prompt and have human annotators indicate which response is better. Train a reward model R(x,y) that predicts a scalar score given a prompt x and response y.

    Step 2: Optimize the LLM with RL. The LLM generates responses, the reward model scores them, and an RL algorithm (typically PPO or GRPO) updates the LLM to produce higher-scoring responses. A KL penalty prevents the LLM from deviating too far from the SFT model, which would lead to reward hacking (exploiting the reward model rather than genuinely improving quality).

    Why RL instead of more supervised learning? Because human preferences are easier to express as comparisons (“A is better than B”) than as absolute labels (“write exactly this response”). RL can optimize for the complex, multi-faceted notion of “good response” captured by the reward model.

    More recent approaches like DPO (Direct Preference Optimization) skip the explicit reward model and optimize preferences directly, simplifying the pipeline while achieving similar results. GRPO (Group Relative Policy Optimization) computes relative advantages within a group of responses, eliminating the need for a separate reward model entirely.

Thread: Loss Functions

  1. Walk me through cross-entropy loss for next-token prediction with a concrete example.

    Suppose the model is predicting the next token after “the cat sat on the”. The vocabulary has 5 candidate tokens: {mat, floor, chair, dog, table}. The true next token is “mat.”

    Step 1: Model produces logits.

    𝐳=[2.1,0.8,0.3,−0.5,0.1]

    Step 2: Softmax converts to probabilities.

    P=[0.55,0.15,0.09,0.04,0.07]

    (Numbers are approximate; they must sum to 1.)

    Step 3: Cross-entropy loss.

    The true label is a one-hot vector:[1, 0, 0, 0, 0] (all probability on “mat”). Cross-entropy simplifies to:

    ℒ=−logP(``mat'')=−log(0.55)≈0.60

    If the model had assigned higher probability to “mat” (say 0.95), the loss would be −log(0.95)≈0.05 (very small, model is confident and correct). If the model had assigned low probability (say 0.01), the loss would be −log(0.01)≈4.6 (very large, model is wrong).

    Step 4: Gradient.

    The beauty of cross-entropy with softmax is that the gradient with respect to the logits has a particularly clean form: ∂ℒ/∂zi=Pi−yi, where yi is 1 for the correct token and 0 for everything else. For our example:

    ∇𝐳ℒ=[0.55−1,0.15−0,0.09−0,0.04−0,0.07−0]=[−0.45,0.15,0.09,0.04,0.07]

    The negative gradient for “mat” tells the model to increase its logit. The positive gradients for other tokens tell the model to decrease theirs. This gradient propagates backward through the entire network, adjusting all weights to make “mat” more likely next time.

  2. What is perplexity and how does it relate to cross-entropy?

    Perplexity is the standard evaluation metric for language models, defined as the exponential of the average cross-entropy loss:

    PPL=exp(−1T∑t=1TlogPθ(xt∣x<t))

    Perplexity has an intuitive interpretation: it measures the effective number of tokens the model is “choosing between” at each step. A perplexity of 10 means the model is, on average, as uncertain as if it were picking uniformly from 10 equally likely tokens. A perplexity of 1 would mean the model predicts every token with certainty.

    Lower perplexity is better. State-of-the-art LLMs achieve perplexity in the single digits on standard benchmarks like WikiText-103 (around 3—​5 for the best models).

    The relationship to cross-entropy is direct: if the average cross-entropy per token isH, then perplexity is 2H (using base-2 log) or eH (using natural log). Since eH is a monotonically increasing function, minimizing cross-entropy automatically minimizes perplexity.

    Perplexity is used rather than raw cross-entropy because it is more interpretable and comparable across datasets with different token counts. However, it has limitations: lower perplexity does not always mean better downstream performance. A model can have low perplexity by being good at predicting common words while still struggling with reasoning or factual accuracy.

  3. Beyond cross-entropy, what other loss functions appear in generative AI systems?

    Several loss functions serve different purposes across the GenAI ecosystem:

    Contrastive loss trains embedding models by pulling similar pairs together and pushing dissimilar pairs apart. The InfoNCE formulation uses a temperature-scaled softmax over similarity scores:

    ℒ=−logexp(sim(𝐳i,𝐳j+)/τ)∑kexp(sim(𝐳i,𝐳k)/τ)

    Used in sentence-transformers, CLIP (image-text matching), and self-supervised representation learning (SimCLR, SimCSE).

    KL divergence loss measures how one probability distribution differs from another:

    DKL(P‖Q)=∑xP(x)logP(x)Q(x)

    Used as a regularizer in RLHF (preventing the policy from drifting too far from the reference model), in VAE training (regularizing the latent space toward a Gaussian prior), and in knowledge distillation (matching the student’s output distribution to the teacher’s).

    DPO loss (Direct Preference Optimization) converts preference pairs into a loss that directly optimizes the LLM without a separate reward model:

    ℒDPO=−logσ(βlogπθ(yw|x)πref(yw|x)−βlogπθ(yl|x)πref(yl|x))

    whereyw and yl are the preferred and dispreferred responses.

    Reconstruction losses (L1/MSE/Huber) measure pixel-level or feature-level differences between predicted and target outputs. Central to image generation (diffusion models, VAEs) but not widely used for text LLMs.

    Reward-based losses: PPO’s clipped surrogate objective maximizes expected reward while constraining the policy update. GRPO computes advantages relative to a group of sampled outputs, eliminating the need for a separate value network.

    Thread: Optimization

    1. How does gradient descent work, and what are SGD and mini-batch SGD?

      Gradient descent updates model parameters in the direction that reduces the loss:

      θt+1=θt−α∇θℒ(θt)

      The gradient∇θℒ points toward the steepest increase in loss, so subtracting it moves toward lower loss. The learning rate α controls the step size.

      Three variants differ in how much data they use to estimate the gradient:

      Batch gradient descent: computes the gradient over the entire training set. Gives the most accurate gradient but is impractical for large datasets (you would need to process trillions of tokens before a single weight update).

      Stochastic gradient descent (SGD): uses a single training example per update. Very fast per iteration but the gradient estimate is extremely noisy, causing erratic updates.

      Mini-batch gradient descent: uses a batch of B examples (e.g., 32 to 4096). This is the practical choice: the gradient estimate is accurate enough for stable progress but computed quickly enough to be practical. All LLM training uses mini-batch gradient descent.

      Batch size has important effects: larger batches give smoother gradients (lower variance, more stable training) but require more memory and may converge to sharper minima that generalize less well. The noise in small-batch gradients can actually help by providing implicit regularization, pushing the optimizer toward flatter minima that tend to generalize better.

    2. What problems does basic SGD have and how does momentum help?

      Plain SGD has several issues:

      Oscillation in narrow valleys. When the loss surface is steep in one direction and flat in another (common in high-dimensional optimization), SGD oscillates across the steep direction while making slow progress along the flat direction.

      Sensitivity to learning rate. Too high and training diverges. Too low and it crawls. Finding the right learning rate requires careful tuning.

      Getting stuck. SGD can slow down dramatically near saddle points (common in high-dimensional loss landscapes) where the gradient is near zero but the point is not a minimum.

      Momentum addresses these issues by adding a velocity term that accumulates past gradients:

      𝐯t=β𝐯t−1+∇θℒ,θt+1=θt−α𝐯t

      The hyperparameterβ (typically 0.9) controls how much history to retain. Think of a ball rolling downhill: momentum keeps it moving in the average downhill direction even when individual gradient steps zigzag. Benefits:

      • Dampens oscillation: the velocity in the oscillating direction cancels out (alternating positive/negative gradients), while the velocity in the consistent direction builds up.

      • Accelerates through flat regions: accumulated velocity carries the parameters forward even when the current gradient is small.

      • Escapes shallow local minima: the accumulated momentum can carry the optimizer over small bumps in the loss landscape.

    3. How did Adam improve on momentum-based methods?

      Adam (Adaptive Moment Estimation) combines two ideas: momentum (smoothed gradients) and adaptive per-parameter learning rates (from AdaGrad/RMSProp).

      Adam maintains two exponential moving averages for each parameter:

      • First moment mt=β1mt−1+(1−β1)gt: the smoothed gradient, similar to momentum.

      • Second moment vt=β2vt−1+(1−β2)gt2: the smoothed squared gradient, estimating the variance.

        After bias correction (to account for the zero initialization):

        m^t=mt1−β1t,v^t=vt1−β2t

        The update is:

        θt+1=θt−αm^tv^t+ϵ

        The key innovation is dividing by v^t: parameters with consistently large gradients get a smaller effective learning rate (preventing overshooting), while parameters with small gradients get a larger effective learning rate (accelerating their learning). This per-parameter adaptation is especially important for LLMs, where different parameter groups (embeddings, attention weights, FFN weights) have very different gradient magnitudes.

        Default hyperparameters (β1=0.9, β2=0.999, ϵ=10−8) work well for most tasks, which is part of Adam’s appeal: it requires less tuning than SGD with momentum. Large-scale LLM pretraining often lowers β2 to around 0.95, which makes the second-moment estimate adapt faster and improves stability on the noisy, large-batch gradients typical of these runs.

      • Why do modern LLMs use AdamW instead of Adam?

        The difference is in how weight decay is applied. Weight decay adds a penalty to prevent weights from growing too large:

        In the original Adam paper, weight decay was implemented as L2 regularization by adding λθ to the gradient:

        gt’=gt+λθt

        The problem: Adam’s adaptive learning rate then scales this decay term differently for each parameter. Parameters with large accumulated gradients (large v^t) get less weight decay, while parameters with small gradients get more. This coupling is unintended and suboptimal.

        AdamW (Loshchilov and Hutter, 2019) decouples weight decay from the gradient update:

        θt+1=(1−αλ)θt−αm^tv^t+ϵ

        Weight decay is applied directly to the weights, independent of the adaptive learning rate. Every parameter decays at the same rate, regardless of its gradient history.

        This seemingly small change makes a measurable difference in generalization. AdamW is the default optimizer for LLaMA, GPT, Mistral, and virtually all modern LLM pretraining runs. Typical weight decay values are λ=0.01 to 0.1.

      • What is a learning rate schedule and why do LLMs use warmup with cosine decay?

        A learning rate schedule varies the learning rate over the course of training rather than keeping it fixed. The standard schedule for LLM training has two phases:

        1. Linear warmup (first 1—​5% of total steps): The learning rate starts at zero (or near-zero) and increases linearly to the peak learning rate. Why warmup?

        • At the start of training, the model’s weights are randomly initialized, so gradients are noisy and unreliable.

        • Large learning rates on noisy gradients cause erratic updates that can permanently damage the model’s representations.

        • Warmup lets the model settle into a reasonable region of parameter space before taking large steps.

        • Adam’s second moment estimates (v^t) need a few steps to become accurate; warmup gives them time to stabilize.

          2. Cosine decay (remaining steps): After warmup, the learning rate follows a cosine curve:

          αt=αmin+12(αmax−αmin)(1+cos(t−twarmupttotal−twarmupπ))

          The rate decreases smoothly from the peak to a minimum value (typically αmin=αmax/10). The cosine shape spends more time at intermediate learning rates (where most useful learning happens) compared to linear decay.

        Why cosine rather than other decay shapes? Empirically, cosine decay consistently produces better results than step decay (abrupt drops) or linear decay (constant decrease). It provides a smooth transition that avoids the sudden instabilities caused by discrete learning rate drops.

        Thread: Training Practicalities

        1. What is overfitting and how do you prevent it in deep learning?

          Overfitting occurs when a model memorizes the training data rather than learning generalizable patterns. The hallmark: training loss is low but validation loss is high. The model performs well on data it has seen but poorly on new data.

          For LLMs, the overfitting landscape is nuanced. During pretraining, classical overfitting is rare because the dataset is enormous (trillions of tokens) and models typically train for less than one epoch. The bigger concern is data repetition: when the same documents appear multiple times, the model can memorize them verbatim. Deduplication of training data is a critical preprocessing step.

          During fine-tuning, overfitting is a real risk because the dataset is much smaller (thousands to millions of examples). Common prevention techniques:

          • Dropout: randomly zero a fraction of activations during training, forcing redundant representations. Typical rate: 0.1.

          • Weight decay (L2 regularization): penalize large weights, encouraging the model to find simpler solutions. Implemented via AdamW.

          • Early stopping: monitor validation loss and stop training when it starts increasing.

          • Data augmentation: for text, this includes paraphrasing, back-translation, or synonym replacement (less common than in computer vision).

          • LoRA/QLoRA: fine-tune only a small number of parameters (low-rank adapters) rather than all weights, dramatically reducing the risk of overfitting.

          • Learning rate: use a smaller learning rate for fine-tuning (1e-5 to 5e-5) compared to pretraining (1e-4 to 3e-4) to make smaller, more conservative updates.

        2. How does weight initialization affect training?

          Weight initialization sets the starting point for optimization. Poor initialization can make training impossible:

          Too large: activations and gradients explode, causing NaN losses within the first few steps. Large initial weights produce large pre-activation values, which through multiple layers compound exponentially.

          Too small: activations and gradients vanish, and the model learns nothing. Each layer produces near-zero outputs, and gradients through the chain rule become negligibly small.

          All zeros: every neuron in a layer computes the same output, receives the same gradient, and updates identically. The symmetry never breaks, and the layer effectively has one neuron. This is called the symmetry breaking problem.

          Good initialization strategies maintain the variance of activations and gradients across layers:

          • Xavier/Glorot (2010): weights drawn from 𝒩(0,2/(nin+nout)). Designed for sigmoid and tanh activations, balancing the variance in both forward and backward passes.

          • He initialization (2015): weights drawn from 𝒩(0,2/nin). Accounts for the fact that ReLU zeroes out half the inputs, so the variance must be doubled to compensate.

          • Scaled initialization for transformers: residual branches are initialized with variance scaled by 1/2L (where L is the number of layers) to prevent the residual sum from growing too large in deep networks.

          In practice, modern deep learning frameworks (PyTorch, JAX) apply appropriate default initialization. But understanding why these defaults exist helps debug training instabilities: if a model produces NaN losses immediately, incorrect initialization is a common culprit.

        3. What is gradient clipping and when is it necessary?

          Gradient clipping limits the magnitude of gradients before the optimizer applies them. The most common approach is max-norm clipping: if the total gradient norm exceeds a threshold c (commonly 1.0), scale the entire gradient vector down:

          if ‖∇θℒ‖2>c:∇←∇·c‖∇‖2

          This preserves the direction of the gradient but caps its magnitude, preventing any single update from being catastrophically large.

          Gradient clipping is necessary because:

          • Gradient spikes: occasional training batches can produce unusually large gradients (due to outlier examples, rare tokens, or numerical issues). Without clipping, these spikes can permanently destabilize training by pushing weights far from a good region.

          • Exploding gradients: in deep networks, the chain rule can amplify gradients through many layers. Even with residual connections and layer normalization, spikes still occur.

          • Mixed-precision training: when using FP16 or BF16 for efficiency, the reduced numerical range makes large gradients more likely to cause overflow.

            Nearly every LLM training pipeline includes gradient clipping with max-norm 1.0. It is one of those techniques that costs almost nothing computationally but prevents rare catastrophic failures that could waste days of GPU time.

          An alternative isvalue clipping: clip each gradient element independently to[−c,c]. This is simpler but can change the gradient direction, so norm-based clipping is generally preferred.

        4. Looking at the full picture, walk me through the training loop of an LLM from data to converged model.

          Here is the end-to-end training pipeline:

          1. Data preparation. Collect trillions of tokens from web crawls, books, code, and curated sources. Clean aggressively: deduplicate, filter low-quality content, remove PII. Tokenize using a BPE (byte-pair encoding) tokenizer with a vocabulary of 32K—​128K tokens. Pack sequences into fixed-length training examples.

          2. Initialize the model. Choose an architecture (number of layers, hidden dimension, number of heads). Initialize weights using scaled initialization. Set up the optimizer (AdamW with β1=0.9, β2=0.95, weight decay 0.1) and learning rate schedule (linear warmup for 2000 steps, cosine decay to αmin).

          3. Training loop (repeat for millions of steps):

          • Sample a mini-batch of sequences from the training data.

          • Forward pass: run the sequences through the model, compute logits at each position.

          • Compute loss: cross-entropy between predicted token probabilities and actual next tokens, averaged over all positions and the batch.

          • Backward pass: compute gradients via backpropagation.

          • Gradient clipping: clip the gradient norm to 1.0.

          • Optimizer step: AdamW updates all parameters using the clipped gradients.

          • Log metrics: record loss, learning rate, gradient norm, throughput (tokens/second).

          • Checkpoint: periodically save model weights and optimizer state for recovery.

          4. Monitoring convergence. Training loss should decrease smoothly (with noise). Sudden spikes indicate issues (data quality, learning rate too high, numerical problems). Perplexity on a held-out validation set tracks generalization. Scaling laws predict the expected final loss given model size and token count, providing a target to aim for.

          5. Distributed training considerations. For models that do not fit on a single GPU, training is distributed using:

          • Data parallelism: each GPU processes a different batch; gradients are averaged (via all-reduce) before the optimizer step.

          • Tensor parallelism: individual layers are split across GPUs (each GPU holds a slice of each weight matrix).

          • Pipeline parallelism: different layers run on different GPUs, with micro-batches flowing through the pipeline.

          • ZeRO: partitions optimizer state, gradients, and parameters across GPUs to reduce memory per GPU.

          6. Post-training. After pretraining converges, the model goes through supervised fine-tuning (SFT) on instruction-response pairs, then RLHF/DPO for alignment. These stages use much smaller datasets (thousands to millions of examples), smaller learning rates (1e-5 to 5e-5), and typically run for 1—​3 epochs with careful regularization to avoid catastrophic forgetting of pretraining knowledge.
